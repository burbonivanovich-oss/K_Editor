# Правила контента, стиль речи и frontmatter

Полные правила редполитики. Краткая сводка — в `CLAUDE.md`. При
сомнениях по конкретному случаю — `docs/editorial-policy.md`
(классы A/B/C для фактчека).

## Структура статьи

- **Длина опорных статей** 1500–2500 слов. Сателлитов — 800–1500.
- **Лид** — конкретный факт или вопрос, не «X является важным
  инструментом». Указываем, что изменилось / когда / кого касается.
- **4–6 H2-секций.** Тема, не вопрос. «Сроки подачи уведомлений», а
  не «Каковы сроки подачи уведомлений?». Форма «Каков/Каковы/Что
  такое» запрещена.
- **FAQ блок** — 3–5 вопросов внизу. Заголовок `## Частые вопросы`.
  Каждый вопрос — реальная формулировка из выдачи.
- **Заключение / Итог** — только если добавляет новое (шаги «что
  делать прямо сейчас»). Раздел, повторяющий лид, удаляем.
- **Горизонтальные разделители `---`** внутри тела статьи — не
  использовать, дробят текст в сборник FAQ.
- **Внутренние ссылки:** минимум 3 на каждую статью, на другие
  материалы из `src/content/blog/` или `src/content/glossary/`.

## Источники

Факты, цифры и нормы — со ссылкой на первоисточник в драфте (НПА,
разъяснения ведомств, «Честный знак»). Голословных утверждений быть
не должно.

**Правовая оговорка:** статья — информационный материал, не
юридическая консультация. Если тема требует прямой оговорки об этом —
формулировать в тексте (обычно в заключении), автоматики нет.

## Категории и теги

- **Categories:** одна основная из пяти: `ts-piot`, `markirovka`,
  `zakonodatelstvo`, `kkt`, `egais`.
- **Tags:** 4–7 штук, лоркейс, по делу.

## Frontmatter-шаблон

```yaml
---
title: "Заголовок: что и почему"
description: "Краткое описание для SERP, до 160 символов."
pubDate: "YYYY-MM-DD"
updatedDate: "YYYY-MM-DD"   # опционально
reviewDate: "YYYY-MM-DD"    # опционально — плановая дата следующей проверки фактов
tags:
  - тег1
  - тег2
categories:
  - ts-piot   # или markirovka, zakonodatelstvo, kkt, egais
draft: false
seo:
  keywords:
    - целевой ключ 1
    - целевой ключ 2
---
```

Модуль не генерирует hero-картинки и og-превью — этим занимается
принимающий проект, если ему это нужно.

## SEO-требования

Модуль не рендерит страницы и не проставляет разметку — эти требования
касаются самого текста, чтобы принимающий проект мог опубликовать его
без доработки:

- **Целевой ключ** — в title, первом абзаце и хотя бы одном H2.
- **Description** 140–160 символов, с ключом и ценностным крючком.
- **Канонический URL** — указывать в `seo.canonical`, только если
  материал — копия другого источника.

## Стиль речи

### Основные принципы

- **Активный залог,** прямые формулировки, минимум канцелярита.
- Никаких эмодзи, кликбейта, восклицательных знаков.
- **Числа — цифрами;** сроки — конкретно (01.07.2026, не «в середине 2026»).
- **Прямое обращение к читателю:** «проверьте», «настройте», «подайте» —
  не «предпринимателям необходимо» или «следует».
- Аудитория — занятый предприниматель: каждое предложение даёт
  информацию, не разгоняет контекст.

### Термины

- **Юридические термины** используем точно: «контрольно-кассовая
  техника» (а не «кассовый аппарат»), «универсальный передаточный
  документ», «налогоплательщик УСН».
- **Разговорные термины,** которые аудитория реально использует, —
  допустимы: «вейпы» (не «электронные системы доставки никотина»),
  «касса» в бытовом контексте. Но не «молочка» — пишем «молочная
  продукция».
- **Сокращения** раскрываем при первом упоминании: ТС ПИоТ, УКЭП,
  ГИС МТ, 54-ФЗ.
- **«Честный знак»** — всегда в кавычках; «система маркировки
  «Честный знак»» при первом упоминании, далее просто ««Честный знак»».

### Запрещённые слова и обороты

Запускать перед сдачей статьи:

```
grep -rni "является\|каковы\|каков \|следует отметить\|необходимо отметить\|таким образом,\|в данном контексте\|выглядит следующим образом\|с точки зрения\|предпринимателям стоит\|предпринимателям необходимо\|в целях\|осуществляет\|осуществляется\|насыщен" src/content/blog/
```

| Паразит | Замена |
|---|---|
| `является` | активный глагол или тире: «X — это Y» |
| `осуществляет/осуществляется` | делает / передаёт / проводит |
| `следует/необходимо отметить` | удалить, сказать прямо |
| `таким образом,` | удалить вводное слово |
| `в данном контексте` | удалить |
| `выглядит следующим образом` | удалить, поставить двоеточие |
| `с точки зрения` | переформулировать конкретно |
| `предпринимателям стоит/необходимо` | прямое обращение: «проверьте» |
| `в целях` | `чтобы` |
| `насыщенный` (о периоде) | назвать конкретно, что изменилось |
| `молочка` | `молочная продукция` |

## Рерайт под соцканалы: правила тона

Формат файла и структура — `docs/content-types.md`, раздел «Рерайт под
соцканалы». Здесь — правила голоса по каждой платформе.

- **Telegram**: сухо и по делу — аудитория читает в ленте, некогда.
  Первые 2 строки должны цеплять без «дорогой читатель». Никаких эмодзи.
- **VK**: чуть теплее, можно риторический вопрос в начале. Хэштеги —
  только релевантные (`#маркировка`, `#УСН`, `#онлайнкасса`).
- **Дзен**: лонгрид-платформа, не пост в ленте. Целевой объём
  4500–5500 знаков, абсолютный коридор 3500–6000. Меньше 3500 —
  алгоритм не покажет в ленте, больше 6000 — падает дочитываемость.
  4–5 H2-заголовков, абзацы по 3–5 предложений, обязательно хотя бы
  один кейс/диалог/конкретная сумма штрафа. Заголовок отличается от
  заголовка исходной статьи (вопрос, кейс или срок).
- **Email**: тема письма — выгода или вопрос ≤ 50 символов. Прехедер
  раскрывает. Один CTA, не два.

## Чего НЕ публикуем

- Прямую коммерческую рекламу решений (не делаем «купи это ПО»).
- Контент без проверки на действующие нормативные акты.
- Статьи с целевым запросом, под который уже есть материал в
  кластере, — обновляем существующий, а не плодим дубли.
