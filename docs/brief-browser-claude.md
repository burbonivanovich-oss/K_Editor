# Бриф для браузерного Клода: скриншоты настройки Google API

Вставить целиком в сессию Claude с расширением для Chrome, залогиненную
в тот Google-аккаунт, где живёт проект Google Cloud и папка Drive.

---

## Контекст

Проект «Контур» — контент-портал для МСБ. Настраивается автоматический
редакционный цикл: бот ведёт контент-план в Google-таблице и выкладывает
статьи отдельными Google Docs в папку Drive. Редактор-человек работает
только в этой папке.

В проекте Google Cloud **уже включены** Drive API и Docs API — на них
работает выгрузка соцпостов. **Не включён Sheets API** — он нужен для
таблицы плана.

Твоя задача — собрать инструкцию по настройке с настоящими скриншотами
и заодно снять слепок текущего состояния проекта.

## Что уже проверено — не перепроверяй

Эти факты сверены с документацией Google в августе 2026, принимай как данность:

1. **`drive.file` достаточно.** Sheets API и Docs API принимают этот скоуп
   для файлов, созданных самим приложением. Таблицу и доки создаёт бот,
   поэтому отдельные `spreadsheets` и `documents` не нужны. `drive.file`
   помечен Google как Recommended / Non-sensitive — верификация приложения
   не требуется.
2. **Полный `auth/drive` брать нельзя** — restricted-скоуп, тянет
   обязательную проверку приложения.
3. **OOB-редирект мёртв.** `urn:ietf:wg:oauth:2.0:oob` отключён: новые
   клиенты запрещены с 28.02.2022, существующие заблокированы с 03.10.2022,
   поток снят полностью 31.01.2023. Замена — `http://localhost`.
4. **Раздел переименован.** «OAuth consent screen» → **Google Auth Platform**
   с вкладками Branding / Audience / Data Access / Clients. Скоупы в
   **Data Access**.
5. **Статус Testing + тип External** = Google отзывает refresh_token через
   7 дней. У Internal и Production такого нет.

## Жёсткие правила

**Замазывай на каждом скриншоте:**

- номер и ID проекта Google Cloud;
- `client_id` и `client_secret`;
- email сервисного аккаунта (`...iam.gserviceaccount.com`);
- личные email, включая список тестовых пользователей;
- любые токены и ключи;
- ID папок и таблиц Drive.

**Никогда не снимай:**

- адресную строку с параметром `code=` после согласия OAuth;
- ответ `curl` с полем `refresh_token`;
- страницу секретов с раскрытым значением.

**Ничего не меняй без отдельного разрешения человека.** Единственное
изменение во всём сценарии — включение Sheets API, и его нужно
подтвердить явным «да» перед нажатием ENABLE. Спроси прямо.

**Не проходи OAuth-поток сам.** Не открывай ссылку согласия, не жми
«Разрешить», не обменивай код на токен. Это порождает боевые учётные
данные — их получает человек своими руками. Твоё дело — снять пустой
экран согласия для иллюстрации, если он попадётся, и описать шаги текстом.

## Задачи

### 1. Слепок текущего состояния

Пройди по консоли и запиши фактами, без скриншотов:

- **Включённые API.** `APIs & Services` → `Enabled APIs & services`.
  Есть ли: Drive API, Docs API, Sheets API, Indexing API, Search Console API.
- **Тип приложения.** Google Auth Platform → Audience: **Internal** или
  **External**?
- **Статус публикации.** Там же: **Testing** или **In production**?
- **Скоупы.** Google Auth Platform → Data Access: полный список. Особенно
  важно, есть ли `drive.file`.
- **Тип OAuth-клиента.** `APIs & Services` → `Credentials` → OAuth 2.0
  Client IDs: **Desktop app** или **Web application**? Если Web — какие
  Authorized redirect URIs заведены (есть ли `http://localhost`).
- **Сервисные аккаунты.** Есть ли они вообще, сколько.

Это самая ценная часть — от неё зависит, сколько шагов вообще нужно.

### 2. Скриншоты

Сними эти экраны. Если какой-то недоступен или выглядит иначе — так и
напиши, не выдумывай.

| № | Экран | Что должно быть видно |
|---|---|---|
| 1 | `APIs & Services` → `Library`, в поиске `google sheets` | Карточка «Google Sheets API» в результатах |
| 2 | Карточка Google Sheets API | Кнопка **ENABLE** крупно |
| 3 | Google Auth Platform → **Audience** | Тип пользователей и статус публикации |
| 4 | Google Auth Platform → **Data Access** | Текущий список скоупов |
| 5 | Панель **ADD OR REMOVE SCOPES**, в фильтре `drive.file` | Строка `.../auth/drive.file` с пометкой Non-sensitive |
| 6 | `APIs & Services` → `Credentials` | Список OAuth-клиентов с колонкой типа |
| 7 | Карточка OAuth-клиента | Блок **Authorized redirect URIs** |
| 8 | Drive: правый клик по папке → «Открыть доступ» | Поле ввода и выпадающий список ролей |

Экраны 5–7 нужны, только если по слепку окажется, что `drive.file` нет
или клиент типа Web application.

### 3. Включить Sheets API

**Сначала спроси разрешение.** Покажи, в каком именно проекте собираешься
включать, и дождись подтверждения. После включения сними результат —
кнопка сменится на MANAGE.

### 4. Собрать инструкцию

Формат — markdown, по-русски, для человека, который к Google Cloud
относится без энтузиазма.

Структура:

1. **Что получилось на входе** — слепок из задачи 1 таблицей.
2. **Сколько шагов реально нужно** — вывод из слепка. Если `drive.file`
   уже есть и Sheets API включён, так и напиши: делать больше нечего.
3. **Шаги** — по одному разделу на шаг, скриншот + подпись + что нажать.
4. **Что осталось человеку** — если нужен новый refresh_token, распиши
   процедуру текстом (ссылка с `redirect_uri=http://localhost`,
   `prompt=consent`, все скоупы разом, обмен кода через curl), но сам её
   не выполняй.
5. **Риск семи дней** — если статус Testing и тип External, объясни, что
   токен умрёт через неделю, и дай три выхода: Internal при наличии
   Workspace, публикация в Production с одним `drive.file`, либо ручное
   обновление раз в неделю.

Стиль: активный залог, прямое обращение, без эмодзи и восклицательных
знаков, даты цифрами. Не пиши «является», «следует отметить», «таким
образом», «в целях».
