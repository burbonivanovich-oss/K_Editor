# Бриф для браузерного Клода: живая проверка опыта редактора

Вставить целиком в сессию Claude с расширением для Chrome, залогиненную
в тот Google-аккаунт, где редактор работает с Drive-папкой проекта
«Контур» (или в личный аккаунт того, кто прогоняет тест — см. «Уровень
1» ниже, ему не нужна папка проекта вообще).

---

## Контекст

Проект «Контур» — модуль-помощник для редакции контента (МСБ РФ,
темы ТС ПИоТ / маркировка / законодательство). Репозиторий:
`burbonivanovich-oss/K_Editor` на GitHub.

Редактор работает **только в Google Drive**: одна папка с таблицей
контент-плана и Google Docs по одной на статью. Он никогда не открывает
GitHub и не видит код. Всё это ведут три автоматические рутины Claude,
CLI-сессия (не эта, другая) их запускает и правит код, но **не может**
физически посмотреть, как таблица и меню выглядят у живого пользователя
в браузере — у неё нет ни залогиненного Google-аккаунта, ни глаз.

2026-08-08 в CLI-сессии прошёл аудит опыта редактора по коду и
документации (без браузера) и нашёл + исправил три расхождения:

1. Сигнал «статья устраивает» раньше нужно было ставить в колонку
   «Статус» — она везде подписана как ботовская и защищена
   (`protectedRange`, подпись «Заполняется автоматически»). Теперь
   значение `принято` добавлено в дропдаун редакторской колонки
   «Решение», и это единственное место, куда его нужно ставить.
2. Опечатка в колонке «Решение» раньше пропадала молча (дропдаун не
   строгий, Sheets принимает любой текст). Теперь нераспознанное
   значение должно вызывать уточняющий комментарий от рутины B к
   ячейке.
3. У таблицы плана не было строки-подсказки под заголовком (у таблицы
   недельного бэклога — была). Добавлена строка 3 с пояснением по
   колонкам «Решение»/«Правка».

Все три правки — в коде и в текстах, которые рендерит Google Sheets API
(`scripts/drive-sync.mjs`). Никто их вживую не видел: это и есть твоя
задача — не выдумывать, а посмотреть, как это на самом деле выглядит и
понятно ли без объяснений человеку, который открывает таблицу впервые.

Полный текст аудита — `docs/audit-2026-08-08-editor-ux.md` в
репозитории, если нужен код и обоснование каждой находки. Инструкция,
которую в итоге получит редактор, — `docs/editor-guide.md`. Обе можно
открыть на GitHub (`github.com/burbonivanovich-oss/K_Editor/blob/main/docs/...`),
доступ публичный на чтение (репозиторий закрытый для записи, не для
чтения — если увидишь 404, репозиторий приватный и тебе нужен GitHub-логин
с доступом; тогда просто читай файлы через `raw.githubusercontent.com`
или спроси у человека текст файла).

## Два независимых уровня проверки — делай тот, что тебе доступен

### Уровень 1 — кнопка «Контур» (не нужен доступ к папке проекта)

Полностью независимая от остального Drive-цикла часть: меню в таблице
дёргает GitHub Actions напрямую через `UrlFetchApp`, минуя Sheets/Docs
API вообще. Для проверки достаточно **любой** твоей личной Google-таблицы
(можно создать новую, пустую) и **одного** GitHub-токена с правом только
`Actions: write` на этот репозиторий — Drive-папка проекта, сервисный
аккаунт, Sheets API не нужны совсем.

Делай этот уровень, если у тебя нет доступа к реальной папке «Контур —
редакция» в Drive, но есть доступ к GitHub-репозиторию
(`burbonivanovich-oss/K_Editor`) с правом создавать fine-grained token.

1. Создай новую пустую Google-таблицу (любое имя, например «Тест кнопки
   Контур»).
2. В ней: **Расширения → Apps Script**. Удали содержимое `Код.gs`,
   вставь целиком файл `integrations/google-apps-script/kontur-menu.gs`
   из репозитория. Сохрани, перезагрузи вкладку с таблицей.
3. В таблице должно появиться меню **Контур**. Если нет — открой Apps
   Script заново, проверь, что `onOpen()` сохранился без ошибок
   (Apps Script подсветит синтаксическую ошибку красным при сохранении).
4. Заполни несколько тестовых строк начиная со строки 5, колонка B —
   любой текст в качестве «темы» (например, «Тестовая тема 1»),
   колонка I (9-я) — любой текст статуса.
5. GitHub → Settings → Developer settings → Fine-grained tokens →
   Generate new token: Repository access → Only select repositories →
   `K_Editor`; Permissions → Actions → **Read and write**; срок — на
   твоё усмотрение, это тестовый токен, после проверки можно отозвать.
   **Полную инструкцию и назначение см. `docs/editor-button.md` в
   репозитории**, если что-то из этого не совпадает.
6. В таблице: меню **Контур → «Настроить доступ (владельцу)»** →
   вставить токен. Замажь токен на любом скриншоте.
7. **Контур → «Проверить связь»** — должен показать имя workflow и
   `state: active`.
8. Встань курсором на строку 5 (с темой). Пройди все три пункта меню
   по очереди: «Срочная правка», «Вопрос по теме», «Док поправлен —
   перечитать». На каждый — введи произвольный текст в диалог (кроме
   recheck — там можно оставить пустым, проверь, что пустое действительно
   проходит).
9. Проверь на GitHub (вкладка **Actions** репозитория) или через
   человека с доступом: появился ли новый run workflow
   `editor-request.yml`, и появился ли новый файл в
   `src/data/editor-requests/*.json` с полями `kind`/`topic`/`note`/`who`.
10. Специально проверь ошибочные пути: встань курсором НЕ на строку с
    темой (например, на пустую строку выше 5) и нажми любой пункт меню —
    должно появиться понятное сообщение «Не видно темы», а не тишина
    или технический текст. Затем: намеренно испорти токен (замени на
    случайную строку через «Настроить доступ»), нажми «Проверить связь»
    — сверь текст ошибки с таблицей кодов в `docs/editor-button.md`
    (401/403/404/422).

### Уровень 2 — полный цикл в таблице плана (нужен реальный Drive-доступ)

Делай этот уровень, только если у тебя есть доступ к настоящей папке
Drive проекта «Контур — редакция» **и** там уже существует таблица
контент-плана (создаётся ботом через `drive-sync.mjs init-cycle` —
у CLI-сессии сейчас нет настроенных Drive-креды, так что скорее всего
такой таблицы ещё нет вообще; если это так, пропусти этот уровень,
уровня 1 достаточно для первой проверки).

Если таблица есть:

1. Открой таблицу контент-плана. Найди строку 3 (между переключателем
   согласования в B2 и заголовками колонок в строке 4). Должна быть
   курсивная серая подсказка про колонки «Решение»/«Правка» и явное
   «не трогайте колонку «Статус»». Прочитай её глазами человека, который
   видит эту таблицу первый раз в жизни: понятно ли, что делать? Не
   обрезается ли текст по ширине колонки?
2. Открой дропдаун в любой ячейке колонки «Решение» (клик на клетку в
   строке с темой). Должны быть варианты: `одобрено`, `убрать`,
   `пишем сами`, `принято`. Проверь, что `принято` там есть — это и есть
   основная правка, которую нужно подтвердить визуально.
3. Попробуй кликнуть в ячейку колонки «Статус» рядом и что-то ввести.
   Google должен показать предупреждение о защищённом диапазоне. Сними
   точный текст этого предупреждения (Google мог сформулировать иначе,
   чем ожидается) — он не наш, могли поменять с последней проверки
   документации.
4. Если в папке цикла есть хотя бы один документ статьи — открой его,
   проверь текст-инструкцию вверху (её пишет `/cycle-batch`, шаблон —
   в `.claude/commands/cycle-batch.md`): должно быть сказано «поставьте
   «принято» в колонке «Решение»», не просто «в строке темы».

## Жёсткие правила

- **Ничего не меняй в реальных production-данных без явного разрешения
  человека.** Уровень 1 — используй только новую, тобой же созданную
  тестовую таблицу, не существующую таблицу проекта. Уровень 2 — если
  есть реальный текущий цикл с живыми темами редактора, не трогай его
  строки: смотри, не редактируй, кроме случаев, явно описанных в шагах
  выше (открыть дропдаун — можно, выбрать из него значение на чужой
  теме — нельзя).
- **Замазывай на скриншотах:** GitHub-токен целиком (даже частично
  видимый), `client_email` сервисного аккаунта, ID папок/таблиц Drive,
  личные email в списках.
- **Не создавай GitHub-токен с правами шире `Actions: write` на этот
  один репозиторий.** Не проси и не используй `GOOGLE_DOCS_KEY`,
  `GSC_CLIENT_ID`/`GSC_CLIENT_SECRET`/`GSC_REFRESH_TOKEN` — это боевые
  секреты проекта, их трогать не нужно ни для одного из двух уровней.
- Тестовую таблицу и токен уровня 1 — удали/отзови после проверки,
  если явно не попросили оставить.

## Что вернуть

- Пройденные шаги по каждому доступному уровню, отметив, что совпало с
  ожиданиями, а что — нет.
- Точные формулировки диалогов и предупреждений Google/Apps Script,
  которые расходятся с текстом в `docs/editor-button.md` или
  `docs/audit-2026-08-08-editor-ux.md` — по ним стоит поправить эти
  файлы в репозитории.
- Скриншоты ключевых экранов (легенда в строке 3, дропдаун «Решение» с
  «принято», диалог защищённого диапазона, диалоги меню «Контур»,
  сообщение об ошибке токена) с замазанными секретами.
- Отдельно — всё, что оказалось непонятным тебе самому при первом
  взгляде на интерфейс, даже если формально всё сработало: это и есть
  то, ради чего затевалась проверка, а не только «работает / не
  работает».
