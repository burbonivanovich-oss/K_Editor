# Переезд на Codex

Как исполнять этот модуль в Codex вместо Claude Code. Документ рабочий:
часть шагов уже сделана в репозитории, часть делает человек руками.

Проверка «не деградирует ли качество» — отдельный документ,
`docs/portability-check.md`. Она выполняется **до** переключения рутин, а
не после.

## Чего этот переезд не касается

Модуль зависит от Google Drive сильнее, чем от любой модели: 1368 строк
`drive-sync.mjs` плюс 267 строк Apps Script. Переезд на другой ИИ — это
точки входа и расписание, работы на день-два. Переезд с Drive — это
рабочее место редактора целиком. Здесь речь только о первом.

## Что уже сделано в репозитории

| Что | Где |
|---|---|
| Тоол-агностичная точка входа | `AGENTS.md` — Codex читает её сам, настройка не нужна |
| Словарь инструментов вместо имён продукта | `AGENTS.md` → «Словарь инструментов»; в процедурах больше нет `WebSearch`/`WebFetch`/`Agent` |
| Скиллы Codex на каждую процедуру | `.agents/skills/<имя>/SKILL.md` — 27 штук, генерируются |
| Субагенты Codex на каждый роль-бриф | `.codex/agents/<имя>.toml` — 5 штук, генерируются |
| Генератор точек входа | `scripts/codex-sync.mjs`, гейт — `npm run codex:check` |
| Текст промпта рутины одной командой | `scripts/routine-prompt.mjs` |
| Запасное расписание на GitHub Actions | `.github/workflows/routines-codex.yml`, выключено до `ROUTINES_ENGINE=codex` |

### Почему точки входа генерируются

Процедуры живут в `.claude/commands/*.md`, роль-брифы — в
`.claude/agents/*.md`. Это канон, и он остаётся каноном: обычный
markdown, читаемый любым инструментом. Скопировать содержание во второй
формат было бы проще всего и хуже всего — два экземпляра расходятся
молча, и расходятся именно там, где текст важен: в шлюзах и запретах.

Поэтому `.agents/skills/` и `.codex/agents/` содержат не пересказ, а
ссылку: имя, `description` для неявного подбора и указание открыть
канонический файл. Меняется процедура — генерировать заново не нужно.
Меняется `description` или появляется новая команда:

```bash
npm run codex:sync
```

Забыли — поймает тест `scripts/codex-sync.test.mjs`, он гоняет
`--check` на реальном репозитории.

Каталог `.claude/` при этом не переименовывается. Имя в пути к данным ни
на что не влияет, а правок потребовало бы в семи скриптах плюс миграцию
файлов фактчека.

## Что делает человек

### 1. Установить Codex и проверить точку входа

Проверено 06.09.2026 на Codex CLI 0.153.4: `AGENTS.md` подхватывается
автоматически, все 27 скиллов из `.agents/skills` доходят до модели.
Проверка не требует обращения к модели и не тратит квоту:

```bash
codex debug prompt-input "проверка" | grep -o 'r5/[a-z0-9-]*/SKILL\.md' | sort -u | wc -l
```

Ожидается 27. Корень `r5` — это `.agents/skills` репозитория; Codex
нумерует корни скиллов и печатает таблицу рядом со списком. Меньше — Codex ищет скиллы в `.agents/skills` от текущего
каталога вверх по дереву, значит запуск был не из корня репозитория.
Команда заодно показывает, какой файл инструкций загружен.

### 2. Проверить субагентов

Включать ничего не нужно: на проверенной версии (0.153.4) субагенты уже
доступны, слотов параллельности четыре — ровно тот потолок, в который
упирается `factcheck-batch` из-за внешнего rate-limit веб-поиска.
Менять `max_concurrent_threads_per_session` в `~/.codex/config.toml` не
нужно и вредно.

Важнее другое, и это выяснилось при проверке. Codex **по умолчанию не
делегирует**: в его системной инструкции прямо сказано не запускать
субагентов, пока об этом не попросит пользователь или `AGENTS.md`.
Поэтому разрешение записано в `AGENTS.md` явно, раздел «Делегирование».
Если его удалить, пайплайн не сломается заметно — он просто начнёт
выполняться одной сессией, и оценку статьи поставит та же сессия,
которая её писала. Это тихая деградация: шлюзы её не поймают, потому что
формально оценка будет.

Остаётся проверить, что определения ролей из `.codex/agents/*.toml`
подхватываются как проектные:

```bash
codex exec -s read-only 'Перечисли доступных тебе субагентов по именам. Ничего не меняй.'
```

В ответе должны быть `research-specialist`, `content-writer`,
`seo-optimizer`, `social-media-manager`, `article-grader`. Их нет —
роли всё равно исполнимы, просто не как именованные субагенты: сессия
читает `.claude/agents/<имя>.md` и выполняет роль сама.

### 3. Прогнать проверку переносимости

`docs/portability-check.md`, одна статья, полдня. Расхождение больше пяти
баллов — разбираться, а не переключать рутины.

### 4. Выбрать механизм расписания

Здесь у Codex есть свои запланированные задачи, и они бывают двух видов.
Разница между ними решает всё:

| Механизм | Работает без включённой машины | Видит репозиторий | Видит локальные файлы | Секреты |
|---|---|---|---|---|
| Задача Codex в приложении | нет — нужны включённая машина и открытое приложение | да, рабочий каталог | да | локальное окружение |
| Облачная задача Codex | да | да, по подключению GitHub | нет | переменные окружения среды |
| `.github/workflows/routines-codex.yml` | да | да | нет | секреты репозитория |

Рутинам цикла нужны Google API по секретам и коммит в репозиторий.
Локальные файлы им не нужны. Значит, подходят второй и третий варианты,
а первый — нет: расписание, которое требует открытого ноутбука в
понедельник в 12:00, расписанием не является.

**Облачная задача** — путь ближе к тому, как рутины работают сейчас:
агентная сессия, которая сама решает. Промпт вставляется в неё текстом,
и вставлять надо ровно то, что версионируется:

```bash
node scripts/routine-prompt.mjs c | pbcopy
```

Скрипт отдаёт текст промпта без паспорта — идентификатор триггера чужой
платформы в задании не нужен. Правило синхронизации то же, что было
(`docs/routines/README.md`): файл — то, что ревьюится, платформа — то,
что исполняется. Расхождение означает, что кто-то поправил рутину
по-быстрому и не донёс правку.

**GitHub Actions** — путь без зависимости от аккаунта и приложения:
расписание, логи и секреты в одном месте, промпт берётся из репозитория
скриптом, разойтись нечему. Требует `OPENAI_API_KEY` в секретах.

Оба варианта рабочие. Actions предсказуемее, облачная задача ближе к
текущему поведению. Смешивать их для одной рутины нельзя — отработает
дважды.

### 5. Завести секреты

`OPENAI_API_KEY` в Settings → Secrets and variables → Actions. Остальные
секреты уже заведены и не меняются — `docs/SECRETS.md`.

### 6. Переключить рутины, по одной

Порядок важен, иначе рутина отработает дважды: сначала выключить её в
Claude Code Remote, потом включить у Codex.

Для варианта с Actions включение — переменная репозитория
`ROUTINES_ENGINE` со значением `codex` (Settings → Secrets and variables
→ Actions → Variables). Пока переменной нет, задания пропускаются: это
предохранитель на время переезда, а не забытая настройка.

Начинать с рутины B — она самая частая и дешёвая, ошибка видна в тот же
день. Рутину C переключать последней: она пишет статьи.

### 7. Опционально — MCP

GitHub MCP подключается в `~/.codex/config.toml`, протокол общий. Без
него `git` и `gh` дают то же самое, чуть медленнее.

## Что остаётся как есть

45+ Node-скриптов, все процедуры и роль-брифы, редполитика, whitelist
НПА, состояние цикла, промпты рутин, брифы ресёрча, каталог материалов
Контура, сверка таблицы, `drive-sync.mjs` и Apps Script, все workflow,
кроме нового. Ни одна строка в них не знает, какая модель их исполняет.

Брифы ресёрча — доказательная база фактчека — лежат в репозитории
(`.claude/research/`, из `.gitignore` выведены намеренно). При смене
инструмента и машины они никуда не денутся.

## Что переносится хуже

**Дисциплина на длинной дистанции.** Процедуры рассчитаны на модель,
которая держит девять стадий со шлюзами в одной сессии и не срезает
углы. Одна проверочная статья этого не покажет: срезать углы модель
начинает на восьмой подряд или к концу батча из трёх. Видно только на
неделе работы. Цена ошибки при этом ниже, чем кажется — шлюзы
детерминированные и ловят деградацию по одной статье, а не по месяцу
контента.

**`CLAUDE.md`.** Остаётся для Claude Code и Codex не мешает: тот читает
`AGENTS.md`. Удалять его не нужно, пока не решено, что назад дороги нет.

## Что проверено на живом Codex, а что нет

Проверено 06.09.2026, Codex CLI 0.153.4, без обращения к модели
(`codex debug prompt-input`):

| Проверено | Результат |
|---|---|
| `AGENTS.md` подхватывается сам | да, вместе с новыми разделами |
| Скиллы из репозитория видны модели | да, все 27 |
| Субагенты доступны | да, четыре слота параллельности |
| Codex делегирует по умолчанию | **нет** — требует явного разрешения, оно добавлено в `AGENTS.md` |

Не проверено, потому что требует обращения к модели, а квота на аккаунте
была исчерпана:

- определения из `.codex/agents/*.toml` подхватываются как именованные
  субагенты (команда — шаг 2; если нет, роли исполнимы чтением брифа);
- `openai/codex-action` с `prompt-file` отрабатывает рутину целиком за
  отведённые 90 минут — проверяется первым ручным запуском workflow
  через `workflow_dispatch`, до включения расписания;
- главное — качество на прогоне статьи, шаг 3.
