# Редакционный цикл: автоматика с редактором в Google Drive

Три рутины Claude ведут контент от плана до выпуска. Редактор согласовывает
план и вычитывает статьи — **только в Google Drive, GitHub он не открывает**.

## Рабочее место редактора

Одна папка Drive, больше ничего:

```
📁 Контур — редакция          ← GOOGLE_DOCS_FOLDER_ID
   📊 Контент-план 2026-08     ← таблица: темы, решения, статусы
   📁 2026-08                  ← папка цикла
      📄 Штраф за работу без ТС ПИоТ
      📄 Маркировка воды с 01.09.2026
      📄 ...                   ← по одному Doc на статью
```

Таблица — пульт: там план, решения редактора и живые статусы.
Доки — тексты: редактор правит прямо в них и комментирует спорное.

## Схема

```
Рутина A ─ /cycle-plan ──────────── 1-е число, 09:00 МСК
  26 тем → таблица в Drive
  content-plan-2026.md НЕ трогает
      ▼
  awaiting_review ◄────────────┐
      │ редактор в таблице     │ правки применены
      ▼                        │
Рутина B ─ /cycle-listen ──────┘  каждые 4 часа, будни
  читает таблицу и комментарии в доках
  нет нового → молчит
      ▼  B2 = «ОДОБРЕН»
  running ── план записан в репозиторий
      │
      ▼
Рутина C ─ /cycle-batch ────────── понедельник и четверг, 08:00 МСК
  3 темы → /create-article ×3 → 3 Google Doc
  СТОП, если у редактора уже 6 статей на вычитке
      ▼
  редактор правит доки, ставит «принято» в таблице
      ▼
Рутина B ── забирает текст из дока → репозиторий → выпуск
      ▼
  темы кончились → done
```

## Пропускная способность

| Параметр | Значение | Где менять |
|---|---|---|
| Размер батча | 3 статьи | `batchSize` |
| Запусков в неделю | 2 (пн, чт) | cron рутины C |
| Потолок очереди редактора | 6 статей | `maxInReview` |
| Тем в плане на месяц | 26 | `--topics` у рутины A |

**Итог: ~26 статей в месяц** при условии, что редактор вычитывает 6 статей
в неделю.

Потолок — это не тормоз, а честный ограничитель. Два батча идут
параллельно, третий не стартует, пока редактор не разгребёт очередь.
Если он вычитывает медленнее — выработка падает автоматически, вместо
того чтобы копить неразобранный хвост. Хотите больше — поднимайте
`maxInReview` и `batchSize`, но упрётесь в скорость вычитки, а не в крон.

## Почему так устроено

**Состояние в файле, а не в сессии.** Рутина каждый раз стартует с чистого
листа. `src/data/editorial-cycle.json` — единственный источник правды.
Меняется только через `scripts/cycle-state.mjs`.

**План не пишется в репозиторий до согласования.** Пока в B2 не стоит
«ОДОБРЕН», `content-plan-2026.md` не меняется.

**Пока статья на вычитке, истина в Google Doc.** Бот не правит файл в
репозитории под редактором. Текст возвращается в git только после
«принято».

**Молчание по умолчанию.** Рутина B срабатывает ~20 раз в неделю.
Уведомление приходит, только когда она реально что-то сделала.

## Состояния

| Цикл | Что значит | Ход за кем |
|---|---|---|
| `idle` | Активного цикла нет | Рутина A |
| `awaiting_review` | План в таблице, ждём B2 = «ОДОБРЕН» | Редактор |
| `running` | План согласован, статьи пишутся и вычитываются | Рутины B и C |
| `done` | Все темы выпущены или сняты | Рутина A |

| Тема | Колонка «Статус» | Что значит |
|---|---|---|
| `planned` | в плане | Ждёт очереди |
| `writing` | пишется | Бот пишет прямо сейчас |
| `review` | на вычитке | Док готов, читает редактор |
| `accepted` | принято | Редактор принял, идёт импорт в репозиторий |
| `released` | выпущено | Опубликовано |
| `dropped` | снято | Редактор убрал тему |

Владелец темы: `bot` — пишет Claude, `editor` — «пишем сами».

## Интерфейс редактора

Всё в таблице. Формат команд знать не нужно, текст свободный.

**Согласование плана целиком** — ячейка **B2**:
`на согласовании` → `ОДОБРЕН` (или `отклонён`).

**По каждой теме** — колонка «Решение», выпадающий список:

| Значение | Что произойдёт |
|---|---|
| *(пусто)* | Тема идёт в работу как обычно |
| `одобрено` | То же явным образом |
| `убрать` | Тема снимается из плана |
| `пишем сами` | Бот не пишет текст. Готовит док с брифом, исследованием и структурой — дальше пишут люди |

**Колонка «Правка»** — свободный текст: «подними приоритет», «добавь про
штрафы», «уже писали в мае», «переформулировать под общепит». Рутина B
разбирает по смыслу и применяет. Непонятное — переспрашивает
комментарием к ячейке.

Ещё можно **править ячейки напрямую**: заголовок, приоритет, целевой
запрос. И **дописать свою строку** внизу — рутина подхватит её как новую
тему.

**По статьям** — правки прямо в Google Doc, спорное комментариями.
Рутина B отвечает в тредах в течение 4 часов. Когда статья устраивает —
«принято» в строке темы, и бот забирает текст в репозиторий.

## Опция «пишем сами»

Тема остаётся в плане и в учёте (календарь, проверка каннибализации),
но текст пишут люди. Бот делает подготовку:

1. Прогоняет `/research-topic` — НПА, сроки, штрафы, источники.
2. Создаёт док с брифом: целевой запрос, структура H2, факты со ссылками
   на первоисточники, требования редполитики, предложенные внутренние
   ссылки с анкорами.
3. Дальше не трогает.

Когда люди напишут и поставят «принято» — статья импортируется в
репозиторий тем же путём, что и ботовская, со всеми проверками.

## CLI

### Состояние цикла

```bash
node scripts/cycle-state.mjs get                    # сводка
node scripts/cycle-state.mjs get --json             # всё состояние

node scripts/cycle-state.mjs init --cycle 2026-08 --plan plan.json \
    --sheet-id <id> --sheet-url <url> --folder-id <id> \
    --batch-size 3 --max-in-review 6

node scripts/cycle-state.mjs apply-decisions --file pull.json
node scripts/cycle-state.mjs can-start-batch        # exit 0 = можно
node scripts/cycle-state.mjs next-batch --size 3
node scripts/cycle-state.mjs start-batch --slugs a,b,c
node scripts/cycle-state.mjs to-review --slug a --doc-id <id> --doc-url <url>
node scripts/cycle-state.mjs accept --slug a
node scripts/cycle-state.mjs release --slug a
node scripts/cycle-state.mjs own --slug a --owner editor
node scripts/cycle-state.mjs sheet-sync             # обновления ячеек
node scripts/cycle-state.mjs reset --force
```

### Google Drive

```bash
node scripts/drive-sync.mjs init-cycle --cycle 2026-08 --plan plan.json
node scripts/drive-sync.mjs pull --sheet-id <id>
node scripts/drive-sync.mjs set-cells --sheet-id <id> --updates '[{"range":"I5","value":"на вычитке"}]'
node scripts/drive-sync.mjs make-doc --title "..." --md article.md --folder <id>
node scripts/drive-sync.mjs export-doc --doc-id <id> --out article.md
node scripts/drive-sync.mjs comments --doc-id <id>
node scripts/drive-sync.mjs reply --doc-id <id> --comment-id <cid> --text "..." --resolve

DRY_RUN=1 node scripts/drive-sync.mjs ...           # без запросов к Google
```

Встроенные предохранители `cycle-state.mjs`:

- `init` не запустится поверх идущего цикла;
- `start-batch` не возьмёт тему, которая уже пишется, вычитывается или
  помечена «пишем сами»;
- `start-batch` не превысит потолок очереди редактора;
- `can-start-batch` — единственный гейт запуска батча.

## Секреты

Секреты те же, что у `drive-sync.mjs`. Настроено всё, кроме одного пункта:

| Секрет | Для чего |
|---|---|
| `GOOGLE_DOCS_KEY` | Сервисный аккаунт: Drive + Docs + Sheets |
| `GOOGLE_DOCS_FOLDER_ID` | Корневая папка редакции в Drive |
| `GSC_CLIENT_ID` / `GSC_CLIENT_SECRET` / `GSC_REFRESH_TOKEN` | Запасной OAuth при исчерпании квоты сервисного аккаунта |

**Что нужно сделать один раз:**

1. Включить **Google Sheets API** в проекте Google Cloud — Drive и Docs
   уже включены, Sheets ещё нет. Без этого `init-cycle` упадёт с
   `Sheets API has not been used in project ... before or it is disabled`.
2. Расшарить корневую папку Drive на email сервисного аккаунта
   (`client_email` из ключа) с правом **Редактор**.
3. Дать редактору доступ к той же папке.

Сервисный аккаунт не имеет собственной квоты Drive: при
`storageQuotaExceeded` скрипт сам переключается на OAuth
`GSC_REFRESH_TOKEN` (`withQuotaFallback` в `drive-sync.mjs`).

## Как поставить рутины на расписание

Расписание в UTC, МСК = UTC+3.

| Рутина | Когда | Cron (UTC) |
|---|---|---|
| A — план | 1-е число, 09:00 МСК | `0 6 1 * *` |
| B — слушатель | каждые 4 часа, будни | `0 5,9,13,17 * * 1-5` |
| C — батч | пн и чт, 08:00 МСК | `0 5 * * 1,4` |

```
create_trigger(
  name: "Контур C — батч статей",
  cron_expression: "0 5 * * 1,4",
  create_new_session_on_fire: true,
  environment_id: "env_01Y9bC1GR6r8J87kbPnMLQCA",
  notifications: { push: true, email: true },
  prompt: "Выполни /cycle-batch. Репозиторий burbonivanovich-oss/K_Editor, ветка main.
           Следуй .claude/commands/cycle-batch.md. Сначала обязательно проверь
           can-start-batch — при ненулевом коде заверши работу молча."
)
```

Аналогично для A и B. Управление — `list_triggers`, `update_trigger`,
`delete_trigger`, `fire_trigger` (запуск вне расписания для обкатки).

> **`notifications` — это не канал до редактора.** Push и email из
> `create_trigger` уходят **владельцу рутины** — тому аккаунту, под которым
> она заведена. Указать в триггере произвольный адрес нельзя: поля для
> этого нет. Если рутину администрирует не редактор (обычный случай),
> редактор о готовом батче так и не узнает, а очередь будет копиться.
>
> Редактора уведомляет сам Drive, и это надо обеспечить отдельно:
> 1. Папка цикла расшарена на **тот же** Google-аккаунт, в котором редактор
>    работает, — с включённым письмом о доступе.
> 2. `/cycle-batch`, выложив доки, оставляет в таблице комментарий с
>    `@`-упоминанием редактора: Google на упоминание шлёт письмо сам.
>    Это единственный способ дотянуться до почты редактора из цикла.
> 3. Проверять раз в цикл, что адрес в шаринге совпадает с рабочим ящиком
>    редактора: смена ящика тихо разрывает уведомления, а симптом —
>    «рутина C молчит неделями» из таблицы ниже.

## Срочный запрос редактора (вне планового прохода)

Рутина B ходит раз в 4 часа по будням. Редактор не может её ускорить: у
него по дизайну нет ни CLI, ни доступа к GitHub — только Google Drive.
Если правка нужна к дедлайну, ждать до четырёх часов нечем оправдать.

**Кнопка в таблице — сделана.** Меню «Контур» в Google-таблице: редактор
жмёт пункт, запрос уходит в `editor-request.yml` и падает в очередь
`src/data/editor-requests/`. Рутина B разбирает очередь первой, до обхода
таблицы, и отвечает по ней всегда — даже если проход в остальном пустой.
Токен лежит в свойствах скрипта на стороне Google, редактор его не вводит
и не видит. Устройство и настройка — `docs/editor-button.md`.

Прежняя колонка «Срочно» кнопкой заменена. Её и не существовало:
`drive-sync.mjs` такую колонку никогда не создавал, так что описанный
здесь механизм всё это время был бумажным.

### Что кнопка не закрывает

Запрос попадает в очередь мгновенно, но саму рутину B кнопка не
запускает: рутины — это триггеры Claude (`create_trigger`), а не GitHub
Actions, и из Apps Script их не дёрнуть. Срочное больше не стоит в общей
очереди за неспешным, но ждать ближайшего прохода всё ещё приходится.

Остаток латентности закрывается одним из трёх способов, и выбор за
владельцем процесса:

1. **Чаще гонять рутину B.** Раз в час вместо четырёх. Самое дешёвое:
   меняется одна строка cron. Платим лишними холостыми запусками —
   правило «нового нет, завершаться молча» делает их дешёвыми, но не
   бесплатными.
2. **Запуск Claude по требованию.** Добавить в `editor-request.yml` шаг с
   Claude Code Action: тогда нажатие кнопки не кладёт запрос в очередь, а
   сразу выполняет `/cycle-listen`. Даёт настоящую реакцию в минуты, но
   требует ключа API и оплаты за каждый прогон.
3. **Договорённость об окне.** Оставить 4 часа, но зафиксировать с
   редактором, что срочные правки подаются до определённого часа. Ничего
   не стоит и ничего не чинит технически — зато снимает неожиданность.

## Обкатка перед автоматикой

1. Включить Sheets API и расшарить папку (см. «Секреты»).
2. `DRY_RUN=1 node scripts/drive-sync.mjs init-cycle --cycle test --plan plan.json`
   — проверить, что скрипт видит окружение.
3. `/cycle-plan --topics 5` — посмотреть таблицу глазами редактора.
4. Поставить в таблице решения: одну тему «убрать», одну «пишем сами»,
   в «Правку» написать что-нибудь свободным текстом.
5. `/cycle-listen` — проверить разбор.
6. Поставить B2 = «ОДОБРЕН», снова `/cycle-listen`.
7. `/cycle-batch` — дождаться доков, открыть, проверить вёрстку.
8. Оставить комментарий в доке, `/cycle-listen` — проверить ответ в треде.
9. Поставить «принято», `/cycle-listen` — статья должна приехать в git.

После этого ставить рутины на расписание.

## Что может пойти не так

| Симптом | Причина | Что делать |
|---|---|---|
| `Sheets API has not been used` | Не включён Sheets API | Включить в Google Cloud Console |
| `storageQuotaExceeded` | У сервисного аккаунта нет квоты Drive | Проверить `GSC_REFRESH_TOKEN` — на него идёт откат |
| `File not found` при `pull` | Папка не расшарена на сервисный аккаунт | Дать доступ Редактора на `client_email` |
| Рутина C молчит неделями | Очередь редактора забита | `cycle-state get` покажет `на вычитке 6/6` |
| Доки развалились на обрывки строк | Не сработала склейка абзацев | Проверить исходный markdown на жёсткие переносы внутри абзаца |
| Редактор удалил строку в таблице | Тема попадает в `missing` | Снять тему вручную или вернуть строку |
| Состояние разъехалось с таблицей | Рутина упала между действием и коммитом | `get --json`, сверить с таблицей, поправить через CLI |

Аварийный выход — `reset --force`, затем `/cycle-plan` заново.
Написанные статьи не теряются: они в git и в Drive.
