## Что осталось

Пять пунктов. Первые два блокируют прогон, третий блокирует корректность

### 1. Drive-секреты в окружении Claude — блокер

Секреты заведены только в GitHub Actions. В сессии Claude их нет:

```bash
node scripts/drive-sync.mjs check
# ✖ нет учётных данных: задай GOOGLE_DOCS_KEY или GSC_CLIENT_ID/SECRET/REFRESH_TOKEN
```

Рутина A0 обходится без них намеренно — публикует не сама, а диспатчем
`backlog-publish.yml`. Рутины A, B и C так не могут: они дёргают
`drive-sync.mjs` пошагово и ветвятся по результату каждого вызова
(`init-cycle` → `pull` → `set-cells` → `make-doc` → `export-doc` →
`comments` → `reply`). Через workflow-мосты это семь диспатчей на один
проход рутины B с передачей состояния артефактами — конструкция, которая
не окупается.

**Скопировать секреты из Actions не выйдет — их сначала надо получить.**
Сервисный аккаунт в этой конфигурации не пишет в Drive вообще: корневая
папка лежит в «Моём диске» живого человека, а не на общем диске, и при
создании файла владельцем становится сервисный аккаунт, у которого своей
квоты Drive нет — `storageQuotaExceeded`. Публикация бэклога 09.08 прошла
не им: `backlog-publish.yml` задаёт `DRIVE_AUTH: oauth` явно, то есть
проект уже работает по пути A из `docs/google-api-setup.md`. Копировать
`GOOGLE_DOCS_KEY` в окружение бессмысленно, а рабочего
`GSC_REFRESH_TOKEN` вне секретов Actions нет.

Развилка — что именно получать:

**Путь B, общий диск (предпочтительно).** Файл на Shared Drive принадлежит
диску, а не создателю, личная квота ни при чём. Сервисный аккаунт
начинает работать, OAuth не нужен, ключ SA бессрочный — семидневных
отзывов токена не бывает. `drive-sync.mjs` это умеет: `supportsAllDrives`
подставляется централизованно, `check` смотрит `driveId` папки и
подсказывает про перенос. Проверять наличие общих дисков надо в Drive
того аккаунта, где лежит папка, — сервисный видит только те, куда его
добавили участником, и его «0 дисков» ничего не значит. Упирается в
политику администратора Workspace.

**Путь A, OAuth (текущий де-факто).** Переполучить `refresh_token` по
`docs/google-api-setup.md`, Шаг 3, и положить `GSC_CLIENT_ID`,
`GSC_CLIENT_SECRET`, `GSC_REFRESH_TOKEN` в окружение. **Сначала**
опубликовать приложение (Google Auth Platform → Audience →
`In production`), иначе токен отзовётся через 7 дней и цикл встанет ровно
тогда, когда пойдёт сам. Файлы создаются от имени владельца аккаунта и
занимают его личные 15 ГБ.

**Путь C, domain-wide delegation** — на случай, если запретят и общий
диск, и публикацию приложения. Сервисный аккаунт имперсонирует
пользователя, файлы принадлежат человеку, `refresh_token` не нужен
совсем. Требует администратора Workspace и доработки кода: `subject` в
JWT сейчас нет.

`GOOGLE_DOCS_FOLDER_ID` нужен при любом пути. На пути A под скоупом
`drive.file` папку нельзя создать руками в браузере — приложение её не
увидит; корневую папку заводит бот, Actions → «Консоль» →
`drive-init-root`.

Само помещение секретов в окружение Claude — осознанный размен: раньше
они жили строго в Actions, теперь их получит любая сессия этого
окружения. Плата за то, что цикл вообще запускается. В git секреты не
попадают, `.gitignore` закрывает `.env`.

**Проверка:** `node scripts/drive-sync.mjs check` в новой сессии —
путь аутентификации определился, `drive.file` с галочкой, запись в папку
проходит.

## Приёмочный прогон

Цель — провести одну настоящую тему по всему пути: план → согласование →
статья → вычитка → приёмка → выпуск, и убедиться, что состояние в
репозитории на каждом шаге совпадает с тем, что видит редактор в Drive.

Берём **5 тем вместо 26** и **батч 2 вместо 3**: прогон должен упереться
в потолок очереди и показать, что предохранитель работает, а не занять
неделю.

Всё делается вручную, в интерактивных сессиях. Рутины на расписание
ставятся последним этапом — раньше нельзя, иначе крон вмешается в прогон.

### Этап 0 — Подготовка

1. Выполнены пункты 1 и 2 из «Что осталось».
2. В свежей сессии Claude:

   ```bash
   node scripts/drive-sync.mjs check      # все креды на месте
   node scripts/health-check.mjs          # 0 fail
   node scripts/cycle-state.mjs get       # состояние idle
   ```

3. Отключён автопрогон (пункт 3). Проверить: `list_triggers`, у
   `trig_011jeEqPGZtRTUiDYFdsZ4Q6` поле `enabled: false`.

**Провал:** `check` ругается на креды — секреты попали не в то окружение
или JSON ключа побился при вставке (частая причина — переносы строк,
безопаснее base64). Состояние не `idle` — доделать предыдущий цикл или
`node scripts/cycle-state.mjs reset --force`.

### Этап 9 — Постановка на расписание

Только после того, как этапы 1–8 прошли. Три рутины, по образцу из
`docs/editorial-cycle.md`:

| Рутина | Команда | Cron (UTC) |
|---|---|---|
| A — план | `/cycle-plan` | `0 6 1 * *` |
| B — слушатель | `/cycle-listen` | `0 5,9,13,17 * * 1-5` |
| C — батч | `/cycle-batch` | `0 5 * * 1,4` |

Все три — `create_new_session_on_fire: true`, окружение то же, где
прописаны Drive-секреты. В промпте C обязательна проверка
`can-start-batch` с завершением молча при ненулевом коде; в промпте B —
правило «нового нет — молчать».

Перед первым плановым запуском: `cycle-state.mjs reset --force` и удалить
тестовую таблицу из Drive, чтобы редактор не путал её с настоящей.
