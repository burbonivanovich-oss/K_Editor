# Проверка переносимости на другой ИИ-инструмент

`AGENTS.md` утверждает, что содержание модуля не привязано к Claude Code
и переносится без потери качества. Утверждение правдоподобное, но до
10.08.2026 его никто не проверял — а стоимость ошибки в нём высокая:
выяснится это в момент, когда переезжать уже нужно.

Здесь — как проверить дёшево и на чём именно споткнуться. Полдня работы,
одна статья, никаких изменений в репозитории.

## Что проверяем

Не «запустится ли», а **не деградирует ли качество**. Шкала для этого
уже есть и от модели не зависит: `/analyze-article` даёт 0–100 по шести
категориям, а шлюзы — детерминированные Node-скрипты с ненулевым кодом
возврата. Модель, которая срезает углы, не пройдёт их молча.

## Порядок

### 1. Взять тему, по которой уже есть результат

Из `src/data/analyze/` выбрать статью с известным баллом. Лучше свежую:
процедуры менялись, старая писалась по другой версии.

### 2. Прогнать её заново на другом инструменте

Открыть `.claude/commands/create-article.md` и выполнить процедуру
целиком — все девять стадий. Тема та же, файл сохранить под другим
именем, чтобы не затереть существующий.

Что заменить по дороге:

| В процедуре написано | Чем заменить |
|---|---|
| `WebSearch`, `WebFetch` | Любой веб-поиск и загрузка страниц |
| «запустить агент research-specialist» | Прочитать `.claude/agents/research-specialist.md` и выполнить роль самому, последовательно |
| Пути `.claude/commands/*` | Тем же путём: это обычные файлы, автозагрузка не требуется |

### 3. Сравнить

```bash
node scripts/factcheck/audit-npa-references.mjs --strict
node scripts/check-seo.mjs src/content/blog/<новый файл>.md
node scripts/check-ai-markers.mjs src/content/blog/<новый файл>.md
node scripts/audit/check-blog-links.mjs
```

Дальше — оценка по `.claude/commands/analyze-article.md` и сравнение с
баллом исходной статьи.

**Разница в пределах 5 баллов — переносимость подтверждена.** Больше —
смотреть, какая категория просела: обычно это «E-E-A-T и фактчек»
(модель хуже проверяет НПА) или «Техника» (пропускает артефакты вроде
брифа на визуал).

### 4. Отдельно проверить, что ломается всегда

Эти места не зависят от качества модели и требуют работы руками:

- **Расписание.** Тут стало лучше 11.08.2026: опрос таблицы, применение
  решений редактора и сверка съехали в `.github/workflows/watch-sheet.yml`
  — обычный cron GitHub Actions, никакого ИИ. Через рутины Claude Code
  остаётся только то, что действительно требует модели: сборка бэклога с
  формулировками тем, написание статей, факчек. Промпты лежат в
  `docs/routines/` и переносятся дословно; механизм запуска для них
  собирается по образцу `backlog.yml` или `watch-sheet.yml`.
- **Каталог `.claude/factchecked/`.** Имя инструмента в пути к данным.
  Переименовывать не обязательно — на работу не влияет, но если решите,
  правок будет семь: `release-article.mjs`, `health-check.mjs`,
  `audit-marker-hashes.mjs`, `maintain-content-queue.mjs`,
  `npa-change-candidates.mjs`, `console.mjs`, pre-commit-хук.
- **Названия инструментов в текстах.** Один проход поиском по
  `.claude/` и `docs/`.

### 5. Чего проверка не покажет

Дисциплину на длинной дистанции. Одна статья не выявит, что модель
начинает срезать углы на восьмой подряд или теряет контекст к концу
батча из трёх. Это видно только на неделе работы — но и цена ошибки
здесь ниже: шлюзы поймают деградацию по одной статье, а не по месяцу
контента.

## Что переносится без вопросов

45+ Node-скриптов, все процедуры и роль-брифы, редполитика, whitelist
НПА, состояние цикла, промпты рутин, брифы ресёрча, каталог материалов
Контура и разрешение перелинковки, сверка таблицы с состоянием. Это
основная масса ценности, и ни одна строка в ней не знает, какая модель её
исполняет.

Отдельно стоит сказать про то, что появилось 11.08.2026 и держит
целостность данных: `scripts/lib/sheet-columns.mjs`,
`scripts/lib/slugify.mjs`, `scripts/lib/resolve-links.mjs` и
`scripts/verify-sheet.mjs`. Это чистый Node без единого упоминания
инструмента, и при переезде они продолжают ловить ровно те же ошибки.

## Настоящая привязка — не модель

Самая крепкая зависимость модуля — Google, а не Claude: 1368 строк
`drive-sync.mjs` плюс 267 строк Apps Script в `kontur-menu.gs`. Переезд
на другую модель — это промпты и расписание. Переезд с Google Drive —
это рабочее место редактора целиком, и стоит он на порядок дороже.
Планируя «а если сменим ИИ», стоит помнить, что сменить Drive было бы
куда больнее.
