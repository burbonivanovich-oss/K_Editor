# Операционная карта модуля

Этот файл — единая точка входа, когда непонятно, что происходит с
модулем. Запустил утилиту → видишь, что в порядке, а где горит. Дальше —
по ссылкам в более детальную документацию.

## Ежедневная проверка состояния

```bash
node scripts/health-check.mjs
```

Отчёт по четырём блокам:
- ✓ зелёный — всё штатно
- ⚠ жёлтый — внимание, не критично
- ✗ красный — нужно чинить

Что проверяется:

- **Контент.** Сколько статей, сколько черновиков, сколько с будущим
  `pubDate`, у скольких нет маркера факт-чека.
- **Workflows.** Все ли скрипты, упомянутые в workflow, реально
  существуют (битая ссылка = красный).
- **Скрипты.** Сколько `.mjs`-файлов в `scripts/`.
- **Документация.** На месте ли ключевые `docs/*.md`.
- **Контент-план.** Статусы тем (`done`/`draft`/`planned`), сверка с
  реальными файлами в `src/content/blog/`, приоритеты, очередь P0.

JSON-вывод для пайплайнов:
```bash
node scripts/health-check.mjs --json
```

## Сверка таблицы с состоянием

```bash
node scripts/verify-sheet.mjs --sheet-id <id>
```

Читает вкладку месяца и сверяет с `src/data/editorial-cycle.json`:
раскладку колонок по заголовкам, статусы, ссылки на доки, ID, приоритеты.
Расхождение — ненулевой код возврата, а не предупреждение.

Проверка есть потому, что 11.08.2026 за день нашлось четыре поломки на
стыке кода и Google Sheets, и все молчаливые: чтение со сдвигом на две
колонки, запись статусов по зашитым буквам в чужие колонки, пустая
колонка ID (все темы цикла числились пропавшими), потеря ссылок на доки
при переносе месяца. Юнит-тесты их не видят — они проверяют машину
состояний, а не то, что лежит в таблице. Все четыре нашлись глазами.

Гоняется автоматически последним шагом `watch-sheet.yml` — после того как
рутина применила решения и обновила таблицу. Логика сравнения покрыта
тестами (`verify-sheet.test.mjs`), каждый воспроизводит реальный случай.

**Коммит рутины означает событие, а не прогон.** `watch-sheet` опрашивает
таблицу раз в три часа по будням (было — раз в час) и коммитит состояние
только когда `cycle-churn.mjs` отвечает `significant`. Отметки прогона
(`updatedAt`, кольцевой `log`) коммита не вызывают; `lastNudgeAt`
вызывает — от него зависит, отправят ли редакции напоминание, и
потерять его значит слать письмо каждый прогон. Замер 24.08.2026: 56
прогонов подряд с нулём решений дали 81 коммит и 4,7 МБ истории у файла
в 26 КБ.

## CI

**Версия Node — одна на весь проект: 22.** Все девять workflow ставят
`node-version: "22"`, `package.json` объявляет `engines.node >= 22`. До
24.08.2026 семь workflow стояли на 20, `watch-sheet` на 22, а разработка
шла на 24: тесты проходили на одной версии, прод работал на другой, и
разойтись они могли молча.

`.github/workflows/ci.yml` — без секретов, гоняется на любом PR и push в
`main`:

1. `node --check` по всем `scripts/**/*.mjs` — синтаксис.
2. `npm test` — `find scripts -name '*.test.mjs' | xargs node --test`,
   рекурсивно по всему дереву `scripts/` (тесты лежат рядом со своим
   скриптом, не только на верхнем уровне). Каждый гоняет реальный CLI
   сабпроцессом на временной фикстуре — ничего в `src/data/` не трогает.
3. `audit-npa-references.mjs --strict` и `check-blog-links.mjs` —
   регрессионные аудиты контента, те же, что в `ops.yml` вручную.
4. `audit-marker-hashes.mjs --strict` — для каждой `draft: false` статьи
   в закоммиченном дереве хеш `.claude/factchecked/<slug>` должен
   совпадать с содержимым файла. Дополняет `pre-commit-factcheck-guard.mjs`:
   тот проверяет staged-содержимое при коммите и обходится
   `--no-verify`, этот — закоммиченное дерево в CI, где обход уже не
   работает.

### Actions пины по SHA, не по плавающему тегу

`actions/checkout`, `actions/setup-node` и подобные закреплены
конкретным commit SHA (`uses: actions/checkout@11d5960a... # v4.4.0`),
не `@v4`: тег можно переставить на другой коммит, SHA — нет. Комментарий
после `#` — для человека, при обновлении версии смотреть SHA нужного
тега:

```bash
git ls-remote --tags https://github.com/actions/checkout v4.5.0
```

и подставить и SHA, и комментарий во всех `.github/workflows/*.yml`, где
используется тот же action.

## Карта команд (slash-команды)

Полный список: одна строка на файл в `.claude/commands/`. Таблица
обязана сходиться с каталогом — команда, которой здесь нет,
не существует для того, кто читает документацию. До 24.08.2026 в списке
было 10 команд из 27.

**Планирование и отбор тем**

| Команда | Что делает | Когда |
|---|---|---|
| `/plan-content` | Процесс 1 из 4: мониторинг новостей, пробелы, приоритеты, обновление контент-плана и календаря | Раз в месяц |
| `/content-calendar` | Редакционный календарь по контент-плану и приоритетам кластеров | После `/plan-content` |
| `/find-topics` | Темы из Wordstat-diff и пробелов контент-плана | Перед новым материалом |
| `/cluster-gaps` | Темы с трафиком, которых нет ни в плане, ни в блоге | При пересборке плана |
| `/demand-watch` | Кластеры блога против свежей частотности Wordstat: что переписать, расширить, переформулировать | Авто, еженедельно |
| `/monitor-rss` | Темы из RSS-источников по актуальным новостям | Еженедельно |
| `/monitor-competitors` | «О чём пишут конкуренты» из аналитики агрегаторов — как детектор тренда, не как источник тем дословно | Ежемесячно |
| `/npa-changes` | Квартальный срез статей с изменившейся нормативкой — отдельный документ редактору или юристу | Раз в квартал |

**Написание**

| Команда | Что делает | Когда |
|---|---|---|
| `/create-article <тема>` | Полный цикл: ресёрч, текст, гейты, оценка. Шлюзы прогоняет скрипт, а не чек-лист | Каждая новая статья |
| `/new-post <тема>` | Быстрый черновик без шлюзов (research → write → seo) | Черновая проработка |
| `/content-pipeline` | Пакетная подготовка нескольких тем плана за один запуск | Когда тем в очереди много |
| `/research-topic <тема>` | Только сбор НПА, сроков, штрафов и кейсов, без написания | Разведка перед решением |
| `/update-article <url>` | Актуализация чужой статьи Маркета: разбор устаревших мест и предложения правок. Новую статью не пишет | Задача типа «актуализировать» |
| `/social-rewrite <slug>` | Рерайт под соцканалы и промостраницу; помнит сделанное, отдаёт редактору в Drive | После приёмки статьи |
| `/design-brief <slug>` | ТЗ дизайнеру на обложку и иллюстрации отдельным Google Doc | По значению «нужно ТЗ дизайнеру» в таблице |

**Проверка и выпуск**

| Команда | Что делает | Когда |
|---|---|---|
| `/factcheck <slug>` | Проверка фактов по первоисточникам: даты, штрафы, ссылки на НПА | Перед передачей редактору |
| `/factcheck-batch` | Пакетная проверка 8–16 статей параллельным dispatch | Раз в неделю или при пачке |
| `/analyze-article <slug>` | Оценка перед передачей редактору: детерминированные проверки pass/fail плюс баллы за то, что скрипт не берёт | Перед `/cycle-batch` |
| `/check-ai <slug>` | Детектор AI-маркеров: шаблонные обороты, структурные признаки | По подозрению |
| `/optimize-seo <slug>` | SEO-аудит и оптимизация статьи или сайта (Яндекс + Google) | При проседании позиций |
| `/release-article <slug>` | Финальный шлюз: снимает `draft` после всех гейтов | Выпуск |
| `/maintain-content` | Процесс 4 из 4: аудит опубликованных статей, решение об обновлении | Раз в неделю |

**Цикл с редактором (рутины)**

| Команда | Что делает | Когда |
|---|---|---|
| `/cycle-backlog` | Рутина A0: недельный бэклог тем с обоснованием таблицей редактору. Помнит отказы и не приносит их повторно | Понедельник |
| `/cycle-plan` | Рутина A: контент-план на цикл таблицей в Drive на согласование. План в репозитории не трогает | Начало цикла |
| `/cycle-listen` | Рутина B: читает решения редактора в таблице и замечания в доках, применяет правки, импортирует принятые статьи | По расписанию |
| `/cycle-batch` | Рутина C: пишет порцию статей (`batchSize`, сейчас 5) и выкладывает в Google Docs. Стопорится при переполнении очереди редактора | Дважды в неделю |
| `/demo-automation` | Демонстрация полного цикла на одной теме (research → writer → seo → соцканалы) | Показ, обучение |

Подробнее по каждой команде — `.claude/commands/*.md` и
`docs/tools.md` раздел «QA-инструментарий».

## Pre-commit гейт (локально)

При `git commit` срабатывают два гейта для статьи с `draft: false`:

- **factcheck-guard** — маркер `.claude/factchecked/<slug>` должен
  существовать, а его хеш совпадать с текущим содержимым статьи (правка
  после факчека маркер аннулирует).
- **seo-guard** — P0-ошибки `check-seo.mjs` (нет title/description,
  категории, тегов, `seo.keywords`, внутренних ссылок, FAQ-блока).

Установка (один раз):
```bash
bash scripts/git-hooks/install.sh
```

Bypass factcheck-guard отдельно (срочные правки, SEO всё равно проверяется):
```bash
SKIP_FACTCHECK_GUARD=1 git commit ...
```

Bypass обоих гейтов сразу:
```bash
git commit --no-verify ...
```

## Если что-то горит

| Симптом | Куда смотреть | Что делать |
|---|---|---|
| Workflow не запустился | GitHub Actions → таб конкретного workflow → история | Триггер настроен? Секреты заполнены? |
| Wordstat не обновился | logs `wordstat-weekly.yml` / `wordstat-kontur.yml` | Токен `YC_API_KEY` жив? `docs/SECRETS.md` |
| Рутина цикла молчит | `node scripts/cycle-state.mjs get` | Состояние `awaiting_review`/потолок очереди? `docs/editorial-cycle.md` |
| «таблица не разобрана» в панели | `npm run status`, строка «Цикл» | Раскладка колонок разъехалась: `node scripts/drive-sync.mjs sync-columns --sheet-id <id>` (сухой прогон), потом `--apply`. Решения редактора при этом **не применялись** — рутина остановилась намеренно |
| Шапка таблицы без цветов, редактор путается, где чья колонка | — | `sync-columns --apply`: он же перерисовывает оформление, даже когда структура колонок уже совпадает |
| В таблице россыпь красных отметок «значение не из списка» | `node scripts/drive-sync.mjs clean-legacy --sheet-id <id>` | Записи уехали не в свою колонку, пока рутина работала со старой раскладкой. Сухой прогон покажет что и где; `--apply` очистит. Работу редактора не трогает — что стирать, а что показать человеку, разобрано в `lib/sheet-junk.mjs` |
| `drive-sync.mjs` падает | `node scripts/drive-sync.mjs check` | Скоупы, включён ли Sheets API — `docs/google-api-setup.md` |
| Cron перестал срабатывать | Actions → конкретный workflow → история | GitHub отключает cron при отсутствии активности 60 дней. Любой push в main возобновляет |
