# Factcheck — проверка фактов в опубликованных статьях

Свой стек проверки claims (дат, штрафов, ссылок на НПА) с автоматическим
извлечением и ручной/агентной верификацией через WebSearch и WebFetch.

> **Покрытие на 2026-05-19: 83/83 (100%).** История backfill'а и
> найденные системные паттерны — в [`docs/factcheck-history.md`](./factcheck-history.md).
> Разбор LLM-галлюцинаций НПА — в [`docs/archive/sessions/session-2026-05-19-postmortem.md`](./archive/sessions/session-2026-05-19-postmortem.md).

## Зачем

Контент про регулирование МСБ устаревает быстро — сроки маркировки,
суммы штрафов в КоАП, постановления правительства меняются часто. Без
проверки статья 6-месячной давности легко содержит неактуальные цифры.

## Структура

```
scripts/factcheck/
  extract-claims.mjs       # regex-парсер: даты, суммы, ст. КоАП, № ФЗ, ссылки
                            # запуск: node scripts/factcheck/extract-claims.mjs <slug>
                            #        node scripts/factcheck/extract-claims.mjs --all
  write-marker.mjs         # маркер .claude/factchecked/<slug> с хешем статьи
                            # запуск: node scripts/factcheck/write-marker.mjs <slug>

src/data/factcheck/
  sources.json             # маппинг типов claims на первоисточники +
                            # список доменов, заблокированных для WebFetch
  inventory.json           # сводка claims по всем 83 статьям (с --all)
  claims/<slug>.json       # claims одной статьи
  results/<slug>.json      # { schemaVersion, articleHash, articleNormHash, policyVersion, claims: [...], summary }

.claude/
  commands/factcheck.md    # /factcheck <slug> — скилл проверки
  factchecked/<slug>       # маркер «статья проверена» — JSON:
                            #   {date, hash, result, criticalMismatches,
                            #    rulesVersion, report}
                            # hash — sha256 статьи на момент проверки;
                            # result/criticalMismatches — из summary
                            # results/<slug>.json, если он есть;
                            # rulesVersion — дата последнего изменения
                            # docs/editorial-policy.md (git-история)
                            # (scripts/factcheck/write-marker.mjs)
```

## Поддерживаемые типы claims

| Тип | Что ловит | Пример |
|---|---|---|
| `DATE_DMY` | дата в формате DD.MM.YYYY | `01.07.2026` |
| `DATE_TEXT` | дата словами | `28 декабря 2025 года` |
| `DATE_YEAR` | год с суффиксом | `2026 году` |
| `DATE_RANGE` | диапазон лет | `2024–2026` |
| `MONEY` | денежная сумма | `15 000 ₽`, `1 млн руб.` |
| `NPA_KOAP` | статья КоАП РФ | `ст. 15.12 КоАП`, `ст. 14.5 ч. 4 КоАП` |
| `NPA_UK` | статья УК РФ | `ст. 171.1 УК РФ` |
| `NPA_NK` | статья НК РФ | `ст. 145 НК РФ` |
| `NPA_FZ` | номер федерального закона | `54-ФЗ`, `289-ФЗ` |
| `NPA_FZ_FULL` | полная формулировка | `Федеральный закон от 01.04.2020 № 102-ФЗ` |
| `NPA_PP_NUMBERED` | постановление Правительства РФ | `постановление Правительства № 1944 от 21.11.2023` |
| `NPA_PRIKAZ` | приказ ведомства | `Приказ ФНС № ЕД-7-20/662@` |
| `PERCENT` | процент | `20%`, `7,5 %` |
| `LINK` | внешняя ссылка | URL из markdown |

Регулярки лежат в `scripts/factcheck/extract-claims.mjs`. Если паттерн не
ловится — добавьте новый и регенерируйте `inventory.json`.

> **Важно:** `\b` под флагом `u` не работает с кириллицей (Cyrillic не
> считается word-char в Unicode mode). Для русских паттернов используем
> `(?<!\d)` / `(?!\d)` и явные ASCII-границы.

### Заблокированные домены

`consultant.ru`, `pravo.gov.ru`, `yandex.*` отдают **403 WebFetch** (anti-bot).
Скилл `/factcheck` выбирает WebFetch или WebSearch по `blocked.domains` из
sources.json — но заблокированный домен означает «возьми документ в другом
месте» (base.garant.ru, rulaws.ru, publication.pravo.gov.ru, сайт ведомства), а
не «сойдёт сниппет». Сниппет подтверждает, что строка где-то встречается; что
она есть в этом документе и в этой редакции — не подтверждает.

### Whitelist НПА и регрессионный аудит

`sources.json.npaWhitelist` содержит реальные действующие НПА (ФЗ, ПП, Приказы,
ст. КоАП/УК) — это машинно-читаемый справочник для двух вещей:

1. `content-writer` использует **только** нормы из brief.sources[] + whitelist.
   Если нужной нормы нет — оставляет плейсхолдер `[НПА: нужна проверка]`,
   не угадывает номер. Это страховка от галлюцинаций (подтверждено фактами:
   за одну сессию пойманы фейковые ПП № 257, № 2456, № 2457 — несуществующие).
2. `scripts/factcheck/audit-npa-references.mjs` пробегает по всем
   опубликованным статьям, извлекает упоминания ПП/Приказов/ФЗ и сверяет
   их с whitelist. Незнакомые номера выводит в отчёт
   `src/data/factcheck/audit/npa-references.json`. Флаг `--strict` —
   ненулевой exit code для CI.

Пополнение whitelist — после успешной верификации в research-specialist:
добавить запись в `sources.json.npaWhitelist.{fz|pp|prikaz}` с полями
`title`, `date`, `topic`.

## Контракт артефактов (C-01, 21.08.2026)

Отчёт и маркер — версионированная связка, которая перепроверяется на
каждом гейте, а не принимается на веру.

| Поле | Где | Что отвечает |
|---|---|---|
| `schemaVersion` | отчёт, маркер | по каким правилам собран артефакт; предыдущая версия зелёной не считается |
| `articleHash` | отчёт | версия текста, на которой факчек реально делали |
| `articleNormHash` | отчёт | смысловой отпечаток: косметическая правка его не меняет, смысловая — меняет |
| `policyVersion` | отчёт, маркер | версия редполитики (дата `docs/editorial-policy.md`) |
| `hash` | маркер | точное содержимое статьи на момент выписки маркера |
| `reportHash`, `claimsHash` | маркер | правка отчёта после выписки маркера |
| `result` | маркер | вердикт, посчитанный из claims (`computeOutcome`), а не переписанный из `summary` |

Проверяет связку один валидатор — `scripts/factcheck/validate-bundle.mjs`.
Его зовут `gates.mjs`, `release-article.mjs`, `health-check.mjs` и CI
(`audit-bundles.mjs --strict`). Раньше каждый смотрел свой набор полей, и
маркер с `passed` проходил везде, хотя отчёт под ним не выдерживал
проверки.

### Доказательство происхождения (D-02)

Для утверждений строгого класса статус `match` требует не «ссылки и цитаты
рядом», а объекта доказательства — что страницу действительно открывали:

```json
{
  "kind": "primary",
  "url": "https://base.garant.ru/...",
  "locator": "пункт 4, абзац 2",
  "retrievedAt": "2026-08-20",
  "effectiveAsOf": "2026-08-20",
  "snapshotHash": "<sha256 полученного текста>",
  "quote": "дословно с этой страницы"
}
```

`kind: "snippet"` — выдача поиска. Для строгого класса она даёт только
`uncertain`: сниппет не доказывает, что строка есть в этом документе и в этой
редакции. Цитата обязана содержать проверяемое значение — не можешь привести
цитату с числом, значит число не проверял.

### Класс риска (D-03)

Строгий режим включается по типу и контексту, а не по объявленной важности
(`scripts/factcheck/risk.mjs`). Строгие — деньги, проценты, доли, сроки и **все
даты**, любые ссылки на НПА, правовые утверждения, технические идентификаторы
(тег, реквизит, версия ФФД). Плюс контекст поверх типа: ответственность и
санкции, вступление требования в силу, прямое указание к действию. `severity`
может поднять класс до строгого, но не может понизить: его ставит тот же, кто
проверяет.

### Покрытие: значение → утверждение → доказательство (D-01)

`check-coverage.mjs` связывает каждое значение статьи с конкретным утверждением,
а не ищет совпадение «где-нибудь в отчёте». У значения есть позиция в тексте
(строка и смещение), у ссылки на норму и у диапазона проверяются **все**
элементы. Три исхода:

* `covered` — разобрано целиком;
* `partial` — утверждение есть, но часть не подтверждена (в статье «ч. 2
  ст. 14.5», в отчёте только «ст. 14.5» — у частей разные санкции);
* `missing` — про значение в отчёте нет ничего.

**Перепривязка маркера запрещена.** `write-marker.mjs` не выпишет маркер,
если смысловой отпечаток текста разошёлся с отчётом: правка «не обязан» →
«обязан» требует полного `/factcheck`, даже если набор чисел не менялся.
Косметическая правка (снятый `draft`, экспорт из Google Docs) маркер
перевыписать позволяет.

## Цикл проверки

```
/factcheck <slug>
   │
   ├── 1. node extract-claims.mjs <slug>     # claims/<slug>.json
   │
   ├── 2. для каждого claim:
   │     ├── lookup в sources.json
   │     ├── если домен в blocked → WebSearch с тематикой+claim
   │     └── иначе → WebFetch с целевым запросом
   │
   ├── 3. сравнить ответ с claim:
   │     ├── match — confidence 0.9+, ничего не делаем
   │     ├── mismatch — расходится, severity critical/moderate/minor
   │     ├── uncertain — не понятно, нужен ручной просмотр
   │     └── missing — нет первоисточника в статье (например, нет ссылки)
   │
   ├── 4. записать results/<slug>.json
   │
   ├── 5. node scripts/factcheck/write-marker.mjs <slug>
   │
   └── 6. вывести summary в чат:
         🔴 critical N → блокировка публикации, draft: true
         🟡 moderate N → правки
         🟢 match N
```

## Severity и action

| Severity | Когда применять | Action |
|---|---|---|
| `critical` | НПА изменился, дата неверна, сумма штрафа отличается ×2+ | Откатить в `draft: true` до правки |
| `moderate` | Часть статьи не указана, формулировка устарела, нет полного контекста | Правки в текущей редакции |
| `minor` | Опечатка, форматирование, лишний предлог | Можно отложить до планового update |

`action` — конкретный тип правки: `rewrite-lede`, `rewrite-bullet`,
`expand-bullet`, `add-references`, `add-disclaimer`, `keep`. В поле
`actionDetail` — готовый текст замены, чтобы не возиться с
переформулировкой.

## Маркетинговый баланс

Источник истины — **`docs/editorial-policy.md`**. Там зафиксированы три
класса правил для каждого типа claims:

- **Класс A** — точность важнее подачи (суммы штрафов, ст. КоАП, технические
  требования). `severity: critical`, переписываем точно.
- **Класс B** — формулировка с маркетинговым акцентом (дедлайны,
  сужение аудитории, тон). Сохраняем формулировку + добавляем
  disclaimer-блок (`action: add-disclaimer`).
- **Класс C** — не проверяем (внутренние ссылки, общие утверждения).

Скилл `/factcheck` обращается к политике на каждом расхождении и применяет
заранее принятое решение. Если ситуация не покрыта политикой —
`status: needs-decision`, оставляем редактору.

**Пример из пилота:** «до 1 июля 2026» в лиде сохранён по правилу B1
(дедлайн как маркетинговый якорь) + blockquote-disclaimer о ПП РФ № 1674
и переходе X-API-KEY. Суммы штрафов поправлены по A1 — точно с вилкой.

## Когда extract-claims не ловит claim

- Числа словами («пятнадцать тысяч рублей») — не покрыто.
- Контекстные даты («с начала года», «через месяц») — не покрыто.
- Пункты НПА без «ст.» («п. 1.2 ПП РФ № 1674») — не покрыто.

Это нормально: фактчек — первый фильтр, а не замена редактору. Если в статье
важные claims «прошли мимо» — добавляйте паттерн и регенерируйте `inventory.json`.
