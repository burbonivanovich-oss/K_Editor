# Промпты рутин — исходники

Здесь лежат тексты, которые исполняют рутины расписания. **Это исходник,
а копия — в платформе**, не наоборот.

## Зачем файлы, если промпты и так живут в Claude

До 10.08.2026 промпты существовали ровно в одном месте — в настройках
Routine в Claude Code on the web. Из этого следовали три проблемы, и все
три обнаружились не в теории:

1. **Ничего не видно в истории.** Промпт рутины A0 меняли 09.08, добавляя
   разбор решений редактора по бэклогу. В репозитории от этой правки нет
   ни следа: `git log` о ней не знает, ревью её никто не делал, откатить
   нечем.
2. **Одна учётная запись — точка отказа.** Тексты доступны только тому,
   у кого есть доступ к аккаунту, где заведены рутины. Уходит человек —
   уходят четыре промпта, восстанавливать которые придётся по памяти.
3. **Миграция на другой инструмент упирается в них же.** `AGENTS.md`
   обещает портируемость и честно называет рутины единственной
   непереносимой частью. Но непереносим там механизм расписания — а вот
   *содержание* промптов переносится дословно, если оно записано. Пока
   оно было только в платформе, при переезде терялось и содержание тоже.

## Правило синхронизации

Меняете промпт рутины — правьте файл здесь и в настройках Routine, одним
заходом, с одинаковым текстом. Файл — то, что ревьюится и версионируется;
платформа — то, что исполняется.

Расхождение между файлом и платформой означает, что кто-то поправил
рутину «по-быстрому» и не донёс правку. Сверить дёшево: открыть рутину и
сравнить с файлом глазами, тексты короткие.

## Что где

| Файл | Рутина | Расписание | Процедура |
|---|---|---|---|
| `a0-backlog.md` | A0 — бэклог тем | понедельник, 9:00 | `.claude/commands/cycle-backlog.md` |
| `a-plan.md` | A — контент-план | 1-го числа | `.claude/commands/cycle-plan.md` |
| `b-listen.md` | B — слушатель | будни, 4 раза в день | `.claude/commands/cycle-listen.md` |
| `c-batch.md` | C — батч статей | понедельник и четверг | `.claude/commands/cycle-batch.md` |

Промпт — это не пересказ процедуры, а точка входа в неё: он говорит,
какой файл открыть, в каком порядке идти и чего не делать ни при каких
обстоятельствах. Подробности живут в `.claude/commands/*.md` и меняются
без правки промптов.

## Текст промпта одной командой

Промпт вставляется в платформу целиком и без паспорта: идентификатор
триггера чужой платформы в задании не значит ничего.

```bash
node scripts/routine-prompt.mjs c        # текст промпта рутины C
node scripts/routine-prompt.mjs c --meta # только паспорт
node scripts/routine-prompt.mjs --list   # какие вообще есть
```

Тот же скрипт кормит `.github/workflows/routines-codex.yml`, поэтому
«скопируй руками нужный кусок» из процесса ушло — а именно оно один раз
уже развело промпты с репозиторием.

## Если переезжаете на другой инструмент

Промпты переносятся текстом как есть: имён инструментов конкретного
продукта в них нет, соответствие описано в `AGENTS.md` → «Словарь
инструментов». Переносится и механизм запуска — по шагам это
`docs/codex-migration.md`, шаг 4, там же сравнение трёх вариантов
расписания и почему один из них не годится.
