# Запланированные задачи на этом компьютере

Выбор владельца от 07.09.2026: исполнять рутины локально в Codex.
Исходники A0/A/B/C и двух задач обслуживания M1/M2 лежат в этой папке.
A0/A/B/C получают текст через `routine-prompt.mjs`, M1/M2 читают свои
файлы напрямую. Этот документ дополняет их правилами общей локальной
копии и имеет приоритет в вопросах блокировки и подготовки доступа.

## Расписание

Задачи подготовлены на паузе, с возвратом в задачу миграции. Их имена:
«Контур M1 — недельный Wordstat», «Контур M2 — данные и источники»,
«Контур A0 — недельный бэклог тем», «Контур A — контент-план»,
«Контур B — обратная связь редактора», «Контур C — батч статей».

| Задача | Модель | Дни | UTC исходника | Europe/Berlin, летнее время | Редакция, UTC+5 |
|---|---|---|---|---|---|
| M1 | GPT-5.6 Luna | понедельник | 04:00 | 06:00 | 09:00 |
| M2 | GPT-5.6 Luna | понедельник и вторник | 05:00 | 07:00 | 10:00 |
| A0 | GPT-5.6 Sol | понедельник | 08:00 | 10:00 | 13:00 |
| A | GPT-5.6 Sol | 1-е число месяца | 08:00 | 10:00 | 13:00 |
| B | GPT-5.6 Luna | будни | 03:00, 07:00, 09:00, 11:00, 13:00 | 05:00, 09:00, 11:00, 13:00, 15:00 | 08:00, 12:00, 14:00, 16:00, 18:00 |
| C | GPT-5.6 Terra | понедельник и четверг | 07:00 | 09:00 | 12:00 |

Локальные задачи настроены по часам Europe/Berlin. **Перед переходом
на зимнее время все часы задач нужно уменьшить на один**, весной вернуть:
редакция и расписание исходников не переходят на летнее время. При смене
часового пояса компьютера также пересверить расписание. Время запуска
не гарантирует отсутствие пересечений: B и C имеют общий слот, A и A0
могут совпасть, а батч может идти дольше часа. Поэтому нужна блокировка ниже.

Компьютер должен быть включён, приложение открыто, папка доступна.
Не рассчитывать на автоматическое восполнение пропущенных запусков.
После простоя сначала проверить очередь и выполнить один нужный проход.
Официальное описание: [Scheduled tasks](https://learn.chatgpt.com/docs/automations?surface=app).

## Перед включением

1. Завершить и сохранить миграционные изменения, открыть в Codex именно
   папку `repo/`. Проверить `npm run codex:check` и `npm test`.
2. Локальный git нужен только для журнала изменений и общей ветки main.
   GitHub не участвует: задачи не вызывают Actions, не делают fetch,
   pull или push. История хранится в локальных коммитах. Workflow в
   `.github/workflows/` оставлены для ручного аварийного запуска, но их
   расписания отключены.
3. Для A/B/C предоставить окружению `GOOGLE_DOCS_FOLDER_ID` и Google-доступ:
   `GOOGLE_DOCS_KEY` для подходящего общего диска либо комплект
   `GSC_CLIENT_ID`, `GSC_CLIENT_SECRET`, `GSC_REFRESH_TOKEN` с
   `DRIVE_AUTH=oauth`. Нужны также настройки из `docs/SECRETS.md`, включая
   `BLOG_BASE_URL` для ссылок в документах. Секреты не писать в промпты,
   отчёты и отслеживаемые файлы. Скрипты читают `process.env`: наличие
   `.env` само по себе не означает, что значения загружены в процесс.
   В локальной задаче запускай каждый Node-скрипт как
   `node --env-file=.env scripts/<имя>.mjs ...`, включая скрипты в
   исходном промпте рутины. Проверить
   `node --env-file=.env scripts/drive-sync.mjs check` именно из среды
   задачи.
4. A0 использует тот же локальный Google OAuth и напрямую вызывает
   `drive-sync.mjs pull`, `append-topics`, `set-cells`,
   `set-row-dropdowns`, `comment` и `verify-sheet`. Команды
   `pull-backlog` и `init-backlog` не использовать: первая отсутствует,
   вторая заменена на `init-month`.
5. Проверить статью по `docs/portability-check.md` в изолированной копии,
   с отдельным оценщиком. Подготовка расписания не подтверждает качество
   генерации и доступность внешних API.
6. Отключить соответствующую Claude Routine и убедиться, что текущий
   проход завершился. Расписания GitHub для `watch-sheet`, `backlog`,
   Wordstat, обхода источников и `routines-codex` удалены из workflow:
   эти операции выполняют локальные M1/M2/A0/B.
7. Включать локальные задачи по одной: M1 → M2 → B → A0 → A → C. Проверять результат
   каждого первого прохода. Запланированные уведомления редакции требуют
   согласованного доступа и адресатов; проверка миграции не отправляет писем.

## Каждый запуск: общая рабочая копия

1. Работай в корне `repo/`. Прочитай `AGENTS.md`. Проверь Node >=22,
   наличие требуемых инструментов и доступа. При недоступности опиши
   конкретный блокер, не делай вид, что рутина выполнена.
2. До любых изменений возьми общую блокировку атомарной командой
   `mkdir .git/codex-editorial-routine.lock`. Успех означает владение.
   Если каталог уже существует, этот проход пропусти и сообщи о задержке.
   Не удаляй чужую блокировку и не запускай цикл параллельно. После сбоя
   владелец снимает оставшуюся блокировку только после проверки, что
   предыдущий проход завершён.
3. Проверь `git status --porcelain` и текущую ветку. При незакоммиченных
   изменениях или ветке, отличной от `main`, остановись с понятной причиной.
   Не делай автоматический stash, reset, checkout и не включай чужие
   изменения в коммит. Не обращайся к origin: все задачи работают с
   одной локальной веткой main.
4. Получи актуальный промпт выбранной рутины скриптом, прочитай его и
   указанную процедуру полностью. Выполни только эту рутину. Состояние
   менять только через `cycle-state.mjs`, выпуск — через release-гейт,
   оценку — отдельным агентом без контекста написания.
5. Коммить только относящиеся к проходу файлы. Не делай push. Общая
   блокировка не допускает параллельную запись другой локальной задачи.
6. Проверь результат по процедуре. У `health-check.mjs` нужно читать
   число `fail` в отчёте: на проверке 07.09.2026 он вернул код 0 даже
   при одном fail. Не объявляй здоровье проекта по одному exit code.
7. На любом пути завершения освободи **свою** блокировку командой
   `rmdir .git/codex-editorial-routine.lock`. При аварийном завершении
   расскажи владельцу о необходимости проверить оставшуюся блокировку.
