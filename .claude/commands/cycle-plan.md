# /cycle-plan — рутина A: план в Google Drive

Запускается 1-го числа месяца в свежей сессии.
Результат — таблица в папке Drive, которую открывает редактор.

**Редактор не заходит в GitHub.** Всё, что он видит, — одна папка Drive:
таблица плана и по одному Google Doc на статью.

**Контент-план в репозитории на этой стадии не меняется.** План живёт в
таблице и в состоянии цикла. В `content-plan-2026.md` он попадёт только
после согласования — это делает рутина B.

---

## Шаг 0 — Проверка, что цикл свободен

```bash
node scripts/cycle-state.mjs get
```

Состояние **не** `idle` и не `done` — СТОП, вывести ссылку на таблицу
текущего цикла и завершиться. Две таблицы плана одновременно — гарантия
путаницы у редактора.

---

## Шаг 1 — Сбор тем

1. `/monitor-rss` — новости за 30 дней.
2. `/cluster-gaps` — пробелы по всем 25 кластерам.
3. `src/data/editorial-plan.json` — отсеять `done` и уже запланированное.
4. `src/data/wordstat/keys.json` — частотности для приоритизации.

Приоритеты — по правилам `/plan-content` (шаг 3):

| Приоритет | Критерий |
|---|---|
| **P0** | Дедлайн ≤ 90 дней ИЛИ активная новость + пробел в кластере |
| **P1** | Спрос 500–2000 без покрытия ИЛИ тренд в источниках |
| **P2** | Полезная тема, нет срочности |

**Объём — 43 темы** (`--topics` переопределяет). Расчёт: порция 5 статей
дважды в неделю — это ~43 статьи в месяц. План меньше выработается за
две-три недели, и рутина C встанет.

Не больше 8 P0 на цикл: если больше — лишние понижаются до P1 с пометкой
в обосновании.

## Шаг 2 — Файл плана

Временный JSON (в scratchpad, не в репозиторий):

```json
[
  {
    "title": "Штраф за работу без ТС ПИоТ в 2026 году",
    "priority": "P0",
    "cluster": "ts-piot",
    "targetKeyword": "штраф за работу без тс пиот",
    "rationale": "Обязанность действует с 28.12.2025, спрос 2400/мес, в кластере нет статьи"
  }
]
```

`slug` не указывать — он соберётся транслитерацией из заголовка.

## Шаг 3 — Таблица в Drive

```bash
node scripts/drive-sync.mjs init-cycle --cycle <YYYY-MM> --plan <файл.json>
```

Скрипт создаёт папку цикла и таблицу `Контент-план <YYYY-MM>` в корневой
папке `GOOGLE_DOCS_FOLDER_ID`, размечает колонки, вешает выпадающие
списки и возвращает JSON с `sheetId`, `sheetUrl`, `folderId`, `folderUrl`.

Структура таблицы:

| Колонка | Кто заполняет | Что в ней |
|---|---|---|
| # | бот | номер |
| Тема | бот, правит редактор | заголовок |
| Приоритет | бот, правит редактор | P0 / P1 / P2 |
| Целевой запрос | бот, правит редактор | ключ |
| Кластер | бот | кластер |
| Зачем сейчас | бот | обоснование |
| **Решение** | **редактор** | список: одобрено / убрать / пишем сами |
| **Правка** | **редактор** | свободный текст |
| Статус | бот | в плане → пишется → на вычитке → принято → выпущено |
| Документ | бот | ссылка на Google Doc статьи |

Ячейка **B2** — согласование плана целиком: `на согласовании` → `ОДОБРЕН`.

Проверить, что при `init-cycle` не было ошибки `Sheets API has not been
used` — если была, значит в проекте Google Cloud не включён Sheets API,
сообщить об этом и остановиться.

## Шаг 4 — Зафиксировать состояние

```bash
node scripts/cycle-state.mjs init \
  --cycle <YYYY-MM> --plan <файл.json> \
  --sheet-id <из вывода> --sheet-url <из вывода> \
  --folder-id <из вывода> --folder-url <из вывода> \
  --batch-size 3 --max-in-review 6
```

Закоммитить и запушить:

```bash
git add src/data/editorial-cycle.json
git commit -m "cycle: план <YYYY-MM> отправлен редактору"
git push -u origin main
```

Состояние обязано попасть в репозиторий: следующая рутина запустится
в другой сессии и прочитает его оттуда.

## Шаг 5 — Позвать редактора

Вывести в итоговый отчёт сессии (отдельного канала оповещений в модуле
нет — редактор узнаёт о плане из письма Google Drive о доступе к таблице):

```
Контент-план <месяц> готов к согласованию: <sheetUrl>

26 тем. Что нужно: пройтись по колонке «Решение» и поставить
«ОДОБРЕН» в ячейке B2, когда план устроит.
```

## Правила

- Контент-план в репозитории не трогать — только после согласования.
- Не создавать вторую таблицу, если цикл уже идёт.
- Не больше 8 P0 на цикл.
- Язык таблицы — только русский.
- Не запускать `/create-article` — это работа рутины C.
