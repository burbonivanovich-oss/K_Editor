# /create-article — статья от темы до черновика

```
▶ /create-article "<тема>"
━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Ресёрч  →  2. Текст  →  3. Гейты  →  4. Оценка
```

До 13.08.2026 здесь было девять стадий и 26 пунктов чек-листов, которые
сессия проверяла по памяти. Четыре из них — SEO, каннибализация,
перелинковка, объём — проверялись глазами при том, что скрипты для них
уже были написаны и лежали рядом: стадия «SEO» не вызывала
`check-seo.mjs` вообще. Стадия оценки заново гоняла те же скрипты, что
отработали раньше, и переводила их вывод в баллы.

Чек-лист, который проверяют глазами, — не проверка, а напоминание. Он
слабеет молча: пункт, однажды не сработавший, в следующий раз
пропускают быстрее. Поэтому всё детерминированное собрано в стадию 3
одной командой, а чтение текста осталось стадии 4.

---

## Стадия 1 — РЕСЁРЧ

### 1.1 Тема и целевой запрос

Из `src/content/wiki/content-plan-2026.md` либо из задачи редакции.
Зафиксировать целевой поисковый запрос — без него нечего проверять
дальше.

### 1.2 Дубль — здесь и только здесь

```bash
node scripts/audit/check-draft-duplication.mjs "<тема или целевой запрос>"
```

| Код | Что делать |
|---|---|
| `0` | Чисто, писать |
| `1`, найденное — черновик | Новую не писать: довести существующий черновик |
| `1`, найденное выпущено | Тему снять, в отчёт — ссылка и пометка «кандидат на обновление» |
| `2` | Писать, но сузить угол и сослаться на найденное |

**Это единственное место, где дубль блокирует.** Дальше по пайплайну он
уже только «требует решения»: находить дубль после написанной статьи
значит терять работу, а выбор между «объединить», «развести углы» и
«canonical» — редакционный, не арифметический.

Отдельной стадии каннибализации больше нет — она дублировала этот шаг и
шаг 1б рутины C, только на три стадии позже.

### 1.3 Каталог Маркета

```bash
node scripts/audit/check-market-duplication.mjs "<тема или целевой запрос>"
```

Не блокер: Маркет решает другую задачу — продажи, не охват. При
совпадении ≥ 0.3 взять URL топ-матча и поставить на него ссылку в
тексте (стадия 2). При ≥ 0.6 — сузить угол или явно дополнить тем, чего
у Маркета нет: штрафы, сроки, конкретный сценарий. Пересказывать нельзя.

Нет файла каталога или он устарел — шаг пропускается без блокировки.

### 1.4 Источники

Категории с НПА, где `research-specialist` **обязателен**:

| Категория | Нормы |
|---|---|
| `ts-piot` | ПП № 1944, 54-ФЗ |
| `markirovka` | отраслевые ПП, ст. 15.12 КоАП, ст. 171.1 УК |
| `zakonodatelstvo` | НК РФ, ТК РФ, КоАП, ФЗ |
| `egais` | ст. 14.16/14.17/14.19 КоАП, 171-ФЗ |
| `kkt` | 54-ФЗ, ст. 14.5 КоАП |

Без research-brief writer не запускается. Это страховка от выдуманных
номеров норм — за прошлые сессии их поймали три штуки.

Бриф: `.claude/research/YYYY-MM-DD-slug-brief.md`, frontmatter с
`sources[]`, у каждого `verified: true` — источник открыт и прочитан, а
не найден в выдаче.

**Шлюз 1** (единственный ручной во всём пайплайне, потому что проверять
нечего — работы ещё нет):

```
[ ] check-draft-duplication дал 0 или решение по правилу записано?
[ ] Категория с НПА → бриф есть, ≥ 3 источника, все verified: true?
[ ] Целевой запрос зафиксирован?
```

## Стадия 2 — ТЕКСТ

Всё, что делает статью статьёй. Проверок здесь нет: они в стадии 3, и
переспрашивать их по ходу незачем.

### 2.1 Текст

Агент `content-writer` с брифом (в Claude Code — субагент; без
субагентов — `.claude/agents/content-writer.md` выполняется самому).

- 1200–2500 слов: лид → 5–7 H2 → FAQ (≥ 4 вопроса) → заключение
- ≥ 3 внутренних ссылки, ≥ 1 ссылка на НПА
- Frontmatter по шаблону из `AGENTS.md`, `draft: true`
- 3 подводки к промоблокам абзацем текста с маркером `[Промоблок: <id>]`,
  `id` из `src/data/cpa-blocks.json` по кластеру статьи

Подводки пишутся здесь, вместе с текстом: вставленная позже читается как
шов.

Файл: `src/content/blog/YYYY-MM-DD-slug.md`

### 2.2 Перелинковка

```bash
node scripts/audit/linkgraph.mjs
```

- **Исходящие**: скорим существующие статьи по совпадению `categories`
  (×2) и `tags` (×1), берём топ-5, ставим ссылки по смыслу — на термин,
  на смежную тему, на продукт.
- **Входящие**: из `linkgraph.json` берём сирот и слабых в той же
  категории, открываем 2–3 донора и добавляем ссылку на новую статью с
  анкором из её заголовка.

Без входящей ссылки статья остаётся сиротой, и гейт это покажет.

### 2.3 Врезки

1–2 штуки, маркером в теле: `[Врезка: штраф]`, `[Врезка: дата]`,
`[Врезка: важно]`, `[Врезка: что сделать]`. Следом абзац содержимого.

Без HTML и блок-цитат: вёрстку делает принимающий проект, а разметка не
переживает выгрузку в Google Doc и обратно. Содержимое — только из
текста статьи, не придумывать.

### 2.4 Факчек

`/factcheck <slug>` — извлечь утверждения, сверить с первоисточниками,
записать маркер. Полная процедура — `.claude/commands/factcheck.md`,
классы решений — `docs/editorial-policy.md`.

**Пропустить нельзя технически**: гейт проверяет не только наличие
маркера, но и хеш текста и отчёт на диске. Правка после факчека делает
маркер недействительным, и стадия 3 это покажет.

### 2.5 Бриф на визуал

`src/data/visuals/<slug>.md`: ТЗ на hero, привязка иллюстраций к H2,
3 подводки к промоблокам.

Модуль не рисует картинки и не собирает страницы — бриф нужен
принимающему проекту. **Шлюзом он больше не является**: качество текста
от наличия ТЗ на обложку не зависит, и блокировать оценку статьи брифом
на иллюстрации — не то же самое, что проверять статью.

## Стадия 3 — ГЕЙТЫ

```bash
npm run gates -- <slug>
```

Один прогон, один отчёт, двенадцать проверок: frontmatter, объём,
внутренние ссылки, SEO, машинный текст, битые ссылки, нормы, факчек,
дубли, каталог Маркета, граф ссылок, опорный материал.

Три исхода вместо двух:

| Вывод | Код | Что значит |
|---|---|---|
| зелёное | 0 | Проверено, вопросов нет |
| красное | 1 | Блокер, дальше не идём |
| требует решения | 2 | Скрипт сузил, выбор за тобой — записать в отчёт |

Красное чинится и прогоняется заново. «Требует решения» не чинится
автоматически: это пересечение с Маркетом, объём на уровне сателлита,
дубль после написания, pillar без ссылки. По каждому — решение одной
строкой в отчёт, чтобы редактор видел, что вопрос заметили, а не
пропустили.

Отдельных чек-листов по SEO, объёму, перелинковке и каннибализации
больше нет. Они здесь.

## Стадия 4 — ОЦЕНКА

```bash
/analyze-article <slug>
```

**Оценивает не эта сессия.** Субагент `article-grader` читает статью с
чистого листа. Автор знает, что хотел сказать, и дочитывает это в текст;
проверяющему видно только написанное. До 13.08.2026 оценку ставил автор
себе сам, и четыре статьи подряд получили 99–100 при живых нарушениях,
записанных в той же оценке.

Баллы 0–100 ставятся за четыре вещи, которые видно только при чтении:
лид, структура, язык, польза. Всё, что посчитал гейт, баллов не приносит
— результаты стадии 3 переносятся в `checks` как есть, повторно скрипты
не гоняются.

**Шлюз 4:** балл ≥ 85, `blocker: false`, и `node scripts/check-analysis.mjs
<slug>` с нулевым кодом.

## Готово

`draft: true` остаётся — публикация это отдельный `/release-article`.

```bash
node scripts/generate-editorial-plan.mjs   # если тема добавлена в контент-план
git add src/content/blog/<slug>.md src/data/visuals/<slug>.md src/data/analyze/<slug>.json
git commit -m "draft: <title>"
```

`.claude/research/` в репозиторий попадает — это доказательная база
факчека, см. `.gitignore`.

## Правила

- Дубль блокирует только на стадии 1. Дальше — решение, не запрет.
- Гейты не обходить и не прогонять «глазами»: глазами там нечего.
- «Требует решения» — записать решение в отчёт, а не пропустить молча.
- Оценивает не тот прогон, который писал.
- Бриф на визуал обязателен как артефакт, но шлюзом не является.
- Статья остаётся `draft: true`.
- Язык — только русский.
