# /design-brief — ТЗ дизайнеру

Берёт готовый текст и превращает его в запрос на визуал: обложка плюс
иллюстрации в тело. Отдаётся дизайнеру Google-доком — дизайнер, как и
редактор, в GitHub не заходит.

Вызов: `/design-brief 2026-08-09-lichnyy-kabinet-onlayn-kassy-kak-voyti-i-chto-tam-nastraivat`

---

## Чем это отличается от Стадии 7 `/create-article`

Стадия 7 уже пишет `src/data/visuals/<slug>.md` — и это не дубль, а
черновик того же самого. Разница в адресате и в моменте:

| | Стадия 7 | `/design-brief` |
|---|---|---|
| Когда | пока статья пишется | когда текст финальный |
| Для кого | для принимающего проекта, в репозиторий | для дизайнера, в Drive |
| Что внутри | сюжет hero и привязка иллюстраций к H2 | то же плюс форматы, размеры, что нельзя, сроки |
| По какому тексту | по черновику | по тексту, который редактор принял |

Поэтому исходник для ТЗ — **финальный** текст статьи, а
`src/data/visuals/<slug>.md` берётся как заготовка: сюжеты оттуда
переносятся, если после правок редактора они всё ещё описывают статью.
Правки часто меняют структуру, и картинка, привязанная к исчезнувшему
разделу, — типичная ошибка этого шага.

---

## Шаг 1 — Собрать исходные данные

```bash
node scripts/design-brief.mjs <slug>
```

Скрипт детерминированно достаёт из статьи всё, что не требует
рассуждения: заголовок, `description`, кластер, H2-структуру, таблицы и
списки (кандидаты на схемы), суммы штрафов и даты (кандидаты на врезки),
объём. И проверяет, что статья вообще существует и не черновик-заготовка.

Ненулевой код — статьи нет или она пустая, дальше идти незачем.

## Шаг 2 — Написать ТЗ

По выводу шага 1 и тексту статьи. Разделы обязательные, порядок такой:

**Обложка.** Сюжет одной фразой; ключевой объект в кадре; настроение;
чего в кадре быть не должно; формат 16:9 с безопасной зоной под
заголовок в верхней трети. Логотипы, узнаваемые интерфейсы, читаемые
суммы и номера НПА на изображении — всегда в запретах: они устаревают
быстрее картинки.

**Иллюстрации.** Две-четыре, каждая привязана к конкретному H2 по
названию раздела. По каждой: тип (схема процесса, таймлайн, сравнение,
чек-лист, скриншот-заглушка), что показать, какой абзац она разгружает.
Не предлагать иллюстрацию туда, где таблица в тексте уже справляется, —
и написать об этом прямо, чтобы дизайнер не искал недостающее.

**Текстовые данные для схем.** Если схема строится по шагам или датам из
статьи — выписать их списком, дословно. Дизайнер не должен вычитывать
статью, чтобы собрать таймлайн.

**Форматы.** Обложка 1200×630 и 16:9; иллюстрации по ширине текста,
макет светлый и тёмный, если принимающий проект использует оба.

**Чего не делать.** Стоковые «бизнесмены у графика», эмодзи, кликбейтные
стрелки и круги, тексты на картинке кириллицей мелким кеглем.

Правила формулировок — те же, что для статьи: без восклицательных
знаков, без оценок, конкретно. Сюжеты берутся из текста статьи, а не
придумываются: если в статье нет кассы, на обложке её быть не должно.

## Шаг 3 — Положить дизайнеру

```bash
node scripts/drive-sync.mjs make-doc --title "ТЗ дизайнеру: <заголовок статьи>" \
  --md src/data/visuals/<slug>-designer.md --folder <folderId цикла>
node scripts/drive-sync.mjs notify --file-id <docId> --to <ящик дизайнера> \
  --message "ТЗ на обложку и иллюстрации: <заголовок статьи>"
```

Ящик дизайнера не задан — шаг пропускается, ссылка на док уходит в
отчёт, и это отмечается отдельной строкой: дизайнер о ТЗ не узнает.

Файл `src/data/visuals/<slug>-designer.md` коммитится вместе со ссылкой
на док в конце файла — чтобы через месяц было видно, по какому тексту
делалось ТЗ.

## Шаг 4 — Отметить в таблице

Ссылку на док вписать в колонку «Комментарий» строки темы одной строкой
«ТЗ дизайнеру: <ссылка>» — своей колонки под визуал в таблице плана нет.
Значение «нужно ТЗ дизайнеру» в колонке «Решение» после этого заменить
на прежнее решение по теме, иначе следующий проход рутины B закажет ТЗ
повторно.

## Шлюз

```
[ ] ТЗ написано по финальному тексту, а не по черновику?
[ ] Каждая иллюстрация привязана к существующему H2 (сверить с текстом)?
[ ] Данные для схем выписаны, дизайнеру не нужно читать статью?
[ ] В запретах есть логотипы, интерфейсы и читаемые суммы?
[ ] Док создан в папке цикла, ссылка записана в таблицу и в файл?
```

## Правила

- ТЗ по принятому редактором тексту, не по черновику на вычитке.
- Сюжеты только из статьи, ничего не придумывать.
- Модуль картинки не рисует и не заказывает подрядчику — он отдаёт
  запрос человеку. Генерация изображений в проект не входит.
- Язык — только русский.
