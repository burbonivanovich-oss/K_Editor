# /cycle-batch — рутина C: батч статей в Google Docs

Запускается **дважды в неделю** — понедельник и четверг, утро.
Пишет 3 статьи за раз, каждую в отдельный Google Doc в папке цикла.

Два запуска по 3 статьи — это ~26 статей в месяц.

---

## Шаг 0 — Предохранитель

```bash
node scripts/cycle-state.mjs can-start-batch
```

**Ненулевой код — СТОП**, вывести причину и завершиться молча.

| Вывод | Что происходит |
|---|---|
| `план ещё не одобрен в таблице` | Ждём согласования, ход за редактором |
| `у редактора на вычитке 6 статей (потолок 6)` | Очередь забита, ждём приёмки |
| `botских тем в очереди нет` | Осталось только то, что редактор пишет сам |
| `цикл в состоянии idle/done` | Активного цикла нет |

Потолок `maxInReview` (по умолчанию 6 = два батча) — это и есть защита
от заваливания редактора. Два батча идут параллельно, третий не стартует.
Никогда не обходить эту проверку.

---

## Шаг 1 — Отобрать темы

```bash
node scripts/cycle-state.mjs next-batch --size 3
```

Возвращает темы со статусом `planned` и `owner: bot`, отсортированные
P0 → P1 → P2. Размер сам ужимается под остаток места в очереди редактора:
если влезает только 2 — вернёт 2.

Темы «пишем сами» сюда не попадают никогда.

---

## Шаг 2 — Пометить в работе

```bash
node scripts/cycle-state.mjs start-batch --slugs <slug1,slug2,slug3>
node scripts/cycle-state.mjs sheet-sync > /tmp/cells.json
node scripts/drive-sync.mjs set-cells --sheet-id <sheetId> --updates "$(cat /tmp/cells.json)"
```

Редактор видит в таблице «пишется» и понимает, что происходит.

---

## Шаг 3 — Написать статьи

Для каждой темы — полный `/create-article "<title>"`, все девять стадий
со шлюзами. Не сокращать пайплайн ради скорости.

Статьи сохраняются в `src/content/blog/` с `draft: true` как обычно —
репозиторий остаётся источником истории версий.

**Обработка сбоев по одной статье:**

- Не прошла шлюз после 2 попыток — не блокировать остальные. Вернуть тему
  в `planned` и записать причину для отчёта.
- Прошла хотя бы одна — батч уходит редактору.
- Не прошла ни одна — доков не создавать, написать в таблицу и в отчёт.

**Бюджет сессии.** Три полных `/create-article` — это много. Если видно,
что сессия не дотянет, довести текущую статью, выложить готовое и
завершиться. Недописанные темы остаются `planned` и попадут в четверг.

## Шаг 4 — Выложить в Google Docs

Для каждой написанной статьи:

```bash
node scripts/drive-sync.mjs make-doc \
  --title "<Заголовок статьи>" \
  --md src/content/blog/<файл>.md \
  --folder <drive.folderId>
```

Скрипт возвращает `docId` и `url`. Frontmatter в док не попадает —
перед выкладкой отрезать его, редактору служебные поля не нужны.

В начало дока добавить короткую врезку для вычитки:

```markdown
## Как вычитывать

Правьте текст прямо здесь — это рабочая версия. Спорные места
отмечайте комментариями, я отвечу в течение 4 часов.

Когда статья устроит — поставьте «принято» в колонке «Решение»
строки темы в таблице плана (не в колонке «Статус» — та моя).
Дальше я заберу текст в репозиторий.

Проверено автоматически: факт-чек зелёный, ссылки на НПА
действующие, check-ai N/10, оценка NN/100, слов NNNN.
```

Привязать док к теме:

```bash
node scripts/cycle-state.mjs to-review --slug <slug> \
  --doc-id <docId> --doc-url <url>
```

## Шаг 5 — Обновить таблицу и состояние

```bash
node scripts/cycle-state.mjs sheet-sync > /tmp/cells.json
node scripts/drive-sync.mjs set-cells --sheet-id <sheetId> --updates "$(cat /tmp/cells.json)"

git add src/content/blog src/data/editorial-cycle.json
git commit -m "cycle: батч N — <k> статей на вычитку"
git push -u origin main
```

Статусы в таблице становятся «на вычитке», в колонке «Документ» —
ссылки. Редактору больше ничего искать не нужно.

## Шаг 6 — Позвать редактора

Одно сообщение на батч, не три:

```
Батч N готов к вычитке — <k> статей:

1. <Заголовок> — <ссылка на док>
2. <Заголовок> — <ссылка на док>
3. <Заголовок> — <ссылка на док>

Таблица плана: <sheetUrl>
У вас на вычитке всего: N из 6. Осталось тем в цикле: M.
```

## Правила

- `can-start-batch` не обходить никогда.
- 3 статьи по умолчанию, меньше — если очередь редактора почти полна.
- Темы «пишем сами» не трогать.
- Frontmatter в Google Doc не выкладывать.
- Статьи остаются `draft: true`. Снимает флаг рутина B, когда редактор
  поставит «принято» в таблице.
- Сбой одной статьи не отменяет батч.
- Язык — только русский.
