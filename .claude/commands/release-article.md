# /release-article — снятие черновика

Последний шаг конвейера. Переводит статью из `draft: true` в
`draft: false` — и только после того, как все гейты реально пройдены.

Вызов: `/release-article 2026-05-01-ts-piot-shtrafy`

**Модуль ничего не публикует.** `draft: false` здесь означает «текст
принят, вычитан и готов к передаче принимающему проекту», а не «вышел на
сайте». Где и когда его разместят — решает принимающая сторона.

Смысл команды в том, что снятие `draft` — единственное место, где можно
обойти весь конвейер одной ручной правкой frontmatter. Поэтому шаг
формализован не как протокол в промпте, а как один детерминированный
CLI: `scripts/release-article.mjs` сам проверяет все гейты в одном и том
же порядке и снимает `draft` только если реально прошли все. Агент
запускает команду, но не воспроизводит выпускной протокол по памяти.

---

## Алгоритм

### Шаг 1 — прогнать гейты и снять draft одной командой

```bash
node scripts/release-article.mjs <slug>
```

Скрипт сам проверяет по порядку:

1. Статья существует и ещё `draft: true` (иначе — сообщает и
   останавливается, ничего не меняя).
2. Тема в `editorial-cycle.json` в статусе `accepted`. Если темы в
   цикле нет вообще (статья написана вне цикла, напрямую через
   `/create-article`) — блокирует и просит явное подтверждение:

   ```bash
   node scripts/release-article.mjs <slug> --confirm-no-cycle
   ```

   Флаг — то самое место, где решение остаётся за человеком: агент не
   ставит его сам без основания, только когда пользователь подтвердил,
   что вычитка была.
3. `audit-npa-references.mjs --strict`, `check-blog-links.mjs`,
   `check-seo.mjs <slug>`, `check-ai-markers.mjs <slug>` — все четыре
   заново, прямо сейчас.
4. `src/data/analyze/<slug>.json` — существует, не старше 30 дней,
   `blocker: false` и `score ≥ 70`. Если файла нет или он устарел,
   скрипт не запускает `/analyze-article` сам (это шаг агента, не
   механическая проверка) — блокирует с понятной причиной:

   ```bash
   /analyze-article <slug>
   node scripts/release-article.mjs <slug>   # повторить
   ```

5. Маркер `.claude/factchecked/<slug>` — существует, хеш совпадает с
   текущим содержимым (иначе статью правили после факчека), `date` не
   старше 180 дней. Нет маркера, хеш разошёлся или дата просрочена —
   блокер: `/factcheck <slug>`, затем повторить команду.

Если что-то не прошло — файл не трогается, в консоль и в `--json`
выводится точная причина по каждому непройденному пункту.

Если прошли все — атомарно: `draft: true → false`, `updatedDate`
проставляется, если статью правили после `pubDate` (по истории git),
`reviewDate` пересчитывается на `pubDate + 6 месяцев`, а если это уже в
прошлом — на `сегодня + 6 месяцев` (статья ждала выпуска слишком долго).

Флаги: `--json` (машиночитаемый отчёт), `--dry-run` (прогнать все
проверки, но не менять файл).

### Шаг 2 — коммит

Скрипт сам не коммитит — это остаётся действием агента:

```bash
git add src/content/blog/<slug>.md
git commit -m "content: <заголовок> (снят черновик)"
```

### Шаг 3 — отчёт

Вывести пользователю отчёт скрипта как есть (без `--json`) — он уже в
нужном формате: список гейтов с ✓/✗/ℹ и итоговый статус
`RELEASED` / `BLOCKED` / `ALREADY_RELEASED`.

## Правила

- **Не снимать `draft` в обход команды.** Ручная правка frontmatter
  обнуляет смысл всех предыдущих гейтов — именно для этого команда и
  формализована как отдельный скрипт.
- **Не чинить статью внутри `/release-article`.** Команда только
  проверяет и переключает флаг. Правки — `/maintain-content <slug>` или
  руками, потом запуск заново.
- **Не обходить блокер** через `--force`, `--no-verify` и подобное —
  таких флагов у `release-article.mjs` и нет. Единственный законный
  обход — `--confirm-no-cycle`, и то по явному решению пользователя.
- Язык отчёта — только русский.
