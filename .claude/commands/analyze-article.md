# /analyze-article — финальная оценка перед передачей редактору

Вызов: `/analyze-article 2026-05-01-ts-piot-shtrafy`

Оценка состоит из двух разных вещей, и смешивать их нельзя:

| Часть | Что это | Влияет на балл |
|---|---|---|
| **Проверки** | Всё, что считает скрипт: SEO, ссылки, НПА, факчек, дубли, маркеры машинного текста | Нет. Только pass/fail и блокер |
| **Баллы** | Только то, что скрипт не берёт: лид, структура, язык, польза | Да, 0–100 |

Скрипт не умеет читать. Балл за то, что скрипт уже проверил, — это не
оценка, а переписывание его вывода другими цифрами.

---

## Почему шкала устроена именно так

Разбор четырёх дыр старой шкалы — в шапке `scripts/check-analysis.mjs`.
Коротко: оценку ставил автор себе сам, замечания записывались и не
стоили баллов, бонус прятал десятку дефицита, а порог 70 не срабатывал
ни разу при разбросе 84–100.

Поэтому арифметику оценки проверяет скрипт: обещание «замечание стоит
балла» в виде строчки инструкции уже один раз не сработало.

---

## Шаг 0 — Кто оценивает

**Оценивает не та сессия, которая писала.** В Claude Code — субагент
`article-grader` (`.claude/agents/article-grader.md`), запускается с
чистого листа: ему дают slug, он сам читает статью. Без субагентов —
отдельный прогон, в котором текст статьи читается заново, а не берётся
из памяти о том, как его писали.

Автор знает, что хотел сказать, и дочитывает это в текст. Проверяющий
читает то, что написано.

---

## Шаг 1 — Проверки (pass/fail)

```bash
npm run gates -- <slug> --json
```

Ничего не пересчитывать руками: гейт уже прогнал все двенадцать проверок
на стадии 3 пайплайна, и его вывод — готовый блок `checks`. Скопировать
как есть.

| Ключ | Что значит провал |
|---|---|
| `frontmatter` | нет обязательного поля, тегов не 4–7, категорий не одна |
| `words` | меньше 800 слов |
| `internalLinks` | меньше 3 внутренних ссылок |
| `seo` | P0-ошибка `check-seo.mjs` |
| `ai` | скор машинного текста ≥ 6 из 10 |
| `links` | битая внутренняя ссылка |
| `npa` | ссылка на недействующую норму |
| `factcheck` | маркера нет, отчёта нет, хеш не сошёлся или факчек не пройден |
| `duplication` | совпадение со своей статьёй (блокером не бывает — решение) |
| `market` | совпадение с каталогом ≥ 0.6 без ссылки (тоже решение) |
| `graph` | на статью никто не ссылается (решение) |
| `pillar` | pillar кластера не ссылается на статью (решение) |

**Неприменимая проверка — законное состояние**, пишется явно:

```json
"pillar": { "applicable": false, "note": "у кластера ts-piot нет опорного материала" }
```

Она не блокирует и **не приносит баллов**. Раньше именно этот случай
нормировался в плюс — отсюда половина завышения.

**Любая упавшая проверка ⇒ `blocker: true`.** Балл при этом всё равно
считается: редактору нужно знать, чинить текст или только ссылки.

## Шаг 1а — Задача статьи и её матрица

Сначала назвать, **что это за работа**, — от этого зависит, что от
статьи вообще требовалось. Одна рубрика на всё оценивает форму: объём,
число секций, наличие FAQ. Форма у инструкции, правового обзора,
сравнения и разбора ошибок одинаковая, а работа разная: инструкция без
«что делать, если шаг не сработал» бесполезна ровно так же, как
сравнение без критериев, — но по числу слов обе выглядят отлично.

`intent` — одно из: `instruction`, `legal-review`, `comparison`,
`troubleshooting`, `explainer`. Матрицы — в `scripts/check-analysis.mjs`
(`INTENT_MATRICES`), там же формулировки пунктов.

| Задача | Пункты матрицы |
|---|---|
| `instruction` | порядок шагов, что нужно до начала, что делать при срыве шага, как убедиться, что получилось |
| `legal-review` | норма у каждого требования, дата вступления, на кого распространяется, что за нарушение |
| `comparison` | критерии названы до сравнения, все варианты по одним критериям, вывод «кому что», нет скрытого победителя |
| `troubleshooting` | вход по симптому, причина у каждого симптома, проверяемость исправления, что делать, если не помогло |
| `explainer` | определение сразу, границы предмета, почему важно сейчас, что делать дальше |

Записывается в оценку рядом с баллами:

```json
"intent": "instruction",
"intentChecks": {
  "steps-ordered": { "ok": true },
  "preconditions": { "ok": true },
  "failure-modes": { "ok": false, "note": "при отказе кассы сказано «обратитесь в поддержку», без разбора" },
  "verification": { "ok": true }
}
```

**Невыполненный пункт — блокер**, а не минус балл: читатель не получил
того, зачем пришёл. И он обязан объяснять, что именно не так, — иначе
автору нечего чинить.

## Шаг 2 — Баллы (0–100, четыре категории по 25)

Читать статью целиком. Балл ставится за то, что видно только при чтении.

### Лид (25)

- Первый абзац отвечает на запрос, а не подводит к ответу.
- Есть конкретика: дата, сумма, номер нормы, ситуация — не «важно понимать».
- 100–150 слов.
- Читатель после лида знает, его ли это статья.

### Структура (25)

- H2 — темы, а не вопросы («Штрафы за работу без ТС ПИоТ», не «Каковы штрафы?»).
- Порядок разделов повторяет порядок действий читателя, а не логику предмета.
- Нет раздела, который можно выкинуть без потери.
- Нет раздела, который держится на одном абзаце общих слов.

### Язык (25)

- Активный залог, прямое обращение.
- Абзацы разной длины и формы. Три подряд одинаковых — замечание,
  даже если каждый по отдельности хорош.
- Нет оговорок без содержания («стоит отметить, что важно учитывать»).
- Термин объяснён при первом употреблении или заменён.

### Польза (25)

- После статьи понятно, что делать, а не только как устроено.
- Числа привязаны к ситуации читателя, а не перечислены.
- Нет обещаний, которых текст не выполняет.
- Спорные места названы спорными, а не сглажены.

**Главный инвариант — баллы и замечания это одно и то же, записанное
двумя способами:**

- есть замечания ⇒ балл ниже максимума, минимум на число замечаний;
- балл ниже максимума ⇒ есть замечания, иначе автор не узнает, что чинить.

Обе стороны проверяются:

```bash
node scripts/check-analysis.mjs <slug>
```

Ненулевой код — оценка оформлена нечестно, а не статья плоха. Чинить
оценку, не статью.

## Шаг 4 — Блокер

`blocker: true`, если:

- балл < **85**, **или**
- упала любая применимая проверка из `checks`, **или**
- не выполнен пункт матрицы задачи (шаг 1а), **или**
- есть замечание веса `blocker` либо одного из трёх видов ниже, **или**
- в `checks` осталась непринятое решение (`decide: true` без `resolution`).

### Замечания, которые не бывают «минус балл»

Три вида замечаний означают, что читатель не получит обещанного, и балл
здесь не шкала, а способ не называть вещи своими именами:

| `kind` | Когда |
|---|---|
| `title-promise` | заголовок обещает то, чего в тексте нет |
| `unproven-instruction` | инструкция без основания: шаги есть, откуда взялись — нет |
| `intent-mismatch` | статья отвечает не на тот запрос, ради которого стояла в плане |

Такое замечание обязано указывать место (`span.line`): «статья не
отвечает на запрос» без строки — это спор, а не правка.

### Решение по проверке «требует решения»

`gates.mjs` отдаёт такие проверки как `{ "decide": true, "resolution": null }`.
Раньше они приезжали сюда как `ok: true`, и «сузить угол и добавить
источник» числилось пройденной проверкой. Решение принимает человек, но
записывается оно целиком:

```json
"market": {
  "decide": true,
  "note": "0.62 — сузить угол или дополнить тем, чего у Маркета нет",
  "resolution": {
    "text": "угол сужен до розницы, ссылка на материал Маркета добавлена в лид",
    "owner": "редактор Ирина",
    "evidence": "https://kontur.ru/market/spravka/1-x",
    "resolvedAt": "2026-08-13"
  }
}
```

Пустое `resolution` — блокер: `release-article.mjs` такую статью не
выпустит.

Порог 85, а не 70: при реальном разбросе 84–100 порог 70 не отсекал
ничего, то есть шлюза не было вовсе.

При `blocker: true` заполнить `blockerReason` одной строкой — что именно
не пустило.

## Правила

- Оценивает не тот прогон, который писал статью.
- Балл за то, что проверил скрипт, не ставится: это pass/fail.
- Каждое замечание стоит хотя бы балла. Проверяется `check-analysis.mjs`.
- Балл снят — замечание записано. Без исключений.
- Бонусных баллов нет. Потолок 100 — это четыре категории по 25.
- Неприменимый критерий не нормируется в плюс, а помечается неприменимым.
- Не редактировать статью внутри `/analyze-article` — он только оценивает.
- Не публиковать статью с баллом < 85 без явного решения владельца.
- Язык отчёта — только русский.
