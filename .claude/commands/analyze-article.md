# /analyze-article — финальная оценка перед публикацией

Свой аналог `/blog analyze` (плагин claude-blog в облачном контейнере не
выживает между сессиями). Считает балл 0–100 по 6 категориям и выводит
блокер-флаг перед передачей статьи редактору.

Вызов: `/analyze-article 2026-05-01-ts-piot-shtrafy`

---

## Шкала 0–100 (6 категорий)

Каждая категория — 0–20 баллов, итого 100 (среднее по 5 ненулевым +
дополнительные за E-E-A-T).

### 1. Качество текста (20)

- **5** Лид (100–150 слов) даёт конкретный факт или вопрос; не «X является важным»
- **5** ≥ 5 H2; заголовки — тема, не вопрос (форма «Каков/Что такое» = -1 балл)
- **5** Объём 1500+ (опорная) или 800+ (сателлит)
- **5** Активный залог, нет паразитов из AGENTS.md (`grep` проверяет)

### 2. SEO (20)

- **5** Целевой ключ в title
- **5** Целевой ключ в первом абзаце
- **5** Целевой ключ хотя бы в одном H2
- **5** Description 140–160 символов, содержит ключ + ценностный крючок

### 3. E-E-A-T и фактчек (20)

- **10** Маркер `.claude/factchecked/<slug>` существует, хеш совпадает с
  текущим содержимым статьи (иначе статью правили после факчека — маркер
  недействителен) и `date` не старше 90 дней
- **5** ≥ 1 ссылка на НПА с указанием статьи и даты
- **5** Все упоминания ПП/Приказов/ФЗ в `audit-npa-references.mjs` whitelist
  (прогон `node scripts/factcheck/audit-npa-references.mjs --strict`)

### 4. Контент-граф (20)

- **4** ≥ 3 исходящих внутренних ссылки на существующие статьи
- **4** ≥ 1 входящая ссылка (из linkgraph.json не в orphans)
- **4** Все внутренние ссылки рабочие (`scripts/audit/check-blog-links.mjs`)
- **4** Pillar-страница своей категории ссылается на эту статью.
  **Критерий применяется, только если `src/content/pillars/<категория>.md`
  существует** — опорный материал есть у 5 кластеров из 25. Нет файла —
  категория оценивается по 16 баллам и нормируется к 20 (балл × 20/16),
  а не штрафуется за отсутствие того, чего в проекте нет.
- **4** Рыночный дедуп (C-01/C-03): `node scripts/audit/check-market-duplication.mjs
  "<title или targetKeyword>"`. Совпадение ниже 0.6 или совпадений нет —
  полный балл, вопрос не встаёт. Совпадение ≥ 0.6 без ссылки на
  найденную статью Маркета в теле — **0**: это не блокер сам по себе
  (см. Шаг 4), но балл честно отражает нерешённый конфликт с каталогом
  продаж. Совпадение ≥ 0.6 со ссылкой на неё — полный балл: конфликт
  снят перелинковкой, ровно то, зачем каталог собран.

### 5. Техника (20)

- **4** Бриф на визуал `src/data/visuals/<slug>.md` существует и содержит
  ТЗ на hero, привязку иллюстраций к H2 и 3 подводки к промоблокам.
  Сам файл изображения не проверяется: модуль картинок не делает, в нём
  нет ни `public/`, ни сборки — их готовит принимающий проект
- **4** Frontmatter полный: title, description, pubDate, tags, categories, seo.keywords, reviewDate
- **4** Tags: 4–7 штук, lowercase, без переспама
- **4** Categories: ровно одна из 25 кластеров (канонический список —
  раздел «Кластеры» в `docs/content-rules.md`, своей копии здесь нет)
- **4** Промоблоки соответствуют кластеру (C-02/C-03): для каждого
  `[Промоблок: <id>]` в тексте проверить `cluster` записи `id` в
  `src/data/cpa-blocks.json`. Кластер статьи **содержит** хотя бы один
  нативный блок (проверить: есть ли в `cpa-blocks.json` записи с этим
  `cluster` вообще) — все три подводки обязаны использовать блоки
  своего кластера, иначе штраф. Кластер **не содержит** нативных
  блоков (как `ts-piot` — 0 из 257 записей) — подводки на соседний
  кластер это ожидаемо, полный балл, но зафиксировать в `issues`
  одной строкой, какой кластер взят вместо своего, чтобы это было
  видно в отчёте, а не только в комментарии `check-seo.mjs`.

### 6. AI Citation (бонус, 0 не блокирует)

- **+5** Q&A-блок в FAQ с короткими 40–60 словными ответами
- **+5** Citation capsule в первом разделе (один абзац, который полностью
  отвечает на запрос — для AI Overviews / Perplexity)

## Алгоритм

### Шаг 1 — Запуск проверок

Параллельно:
```bash
node scripts/audit/check-blog-links.mjs
node scripts/factcheck/audit-npa-references.mjs --strict
node scripts/audit/linkgraph.mjs
node scripts/audit/check-market-duplication.mjs "<title статьи>"
```

Последний — вход для критерия «Рыночный дедуп» в Контент-графе, не
блокер сам по себе. `cpa-blocks.json` для критерия «Промоблоки
соответствуют кластеру» читать напрямую (без отдельного скрипта) —
нужно только посчитать, сколько записей с `cluster` статьи там есть.

### Шаг 2 — Чтение статьи

Прочитать `src/content/blog/<slug>.md`. Распарсить frontmatter.

### Шаг 3 — Оценка по 6 категориям

Для каждой категории посчитать балл по чек-листу выше. Зафиксировать в
структуру:

```json
{
  "slug": "...",
  "score": 87,
  "blocker": false,
  "categories": {
    "quality": { "score": 18, "issues": [...] },
    "seo": { "score": 20, "issues": [] },
    "eeat": { "score": 15, "issues": ["маркер factcheck старше 90 дней"] },
    "graph": { "score": 17, "issues": ["pillar zakonodatelstvo не ссылается"] },
    "tech": { "score": 17, "issues": ["tags: 8 штук (норма 4–7)"] },
    "ai_citation": { "score": 5, "issues": [] }
  },
  "checkedAt": "YYYY-MM-DD"
}
```

Записать в `src/data/analyze/<slug>.json`.

### Шаг 4 — Блокер-флаг

`blocker: true` если:
- Балл < 70, **или**
- Маркер factcheck отсутствует / старше 180 дней, **или**
- `audit-npa-references.mjs --strict` упал, **или**
- `check-blog-links.mjs` упал.

### Шаг 5 — Отчёт

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 /analyze-article <slug>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Балл: XX/100   [✓ PASS / ✗ BLOCKER]

  Качество текста      18/20  ✓
  SEO                  20/20  ✓
  E-E-A-T + factcheck  15/20  ⚠  маркер старше 90 дней
  Контент-граф         17/20  ⚠  pillar zakonodatelstvo без ссылки
  Техника              17/20  ⚠  tags: 8 (норма 4–7)
  AI Citation           5/10  +  можно добавить citation capsule

Что исправить (приоритет):
  1. ...
  2. ...

Detail: src/data/analyze/<slug>.json
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## Интеграция в цикл

Шлюз обязателен. Если `blocker: true` — статья дальше не идёт: выводится
список правок, пользователь их вносит и запускает `/analyze-article`
заново. Снять `draft` может только `/release-article`, и он проверяет
результат этой оценки на свежесть — старый проходной балл не засчитается
после правок.

Не обходить блокер через `--no-verify` или подобное. Это гигиена контента.

## Правила

- Не публиковать статью с баллом < 70 без явного решения пользователя.
- Не редактировать статью внутри `/analyze-article` — он только оценивает.
  Правки делает либо человек, либо запуск `/maintain-content <slug>`.
- Язык отчёта — только русский.
