# Контур — инструкции для Claude Code

Общие правила проекта, редполитика и структура — в
[`AGENTS.md`](./AGENTS.md). Он написан тоол-агностично специально для
того, чтобы проект было легко перенести на другой агентный ИИ-инструмент
(например, ChatGPT/Codex) без потери качества — см. там раздел
«Портируемость». Ниже — то, что специфично именно для Claude Code.

@AGENTS.md

## Субагенты (`.claude/agents/`)

`research-specialist`, `content-writer`, `seo-optimizer`,
`social-media-manager`, `article-grader` — запускаются через инструмент
Agent, обычно параллельно и в фоне, с асинхронным уведомлением по
завершении. `article-grader` — исключение: он запускается **после**
остальных и намеренно с чистого листа, потому что оценивать свою работу
той же сессией нельзя (см. `.claude/commands/analyze-article.md`). Каждый
файл — самодостаточный роль-бриф на чистом markdown: без Claude Code
его тоже можно прочитать и выполнить вручную, последовательно (детали —
`AGENTS.md` → «Портируемость»).

## Slash-команды и Skills (`.claude/commands/`)

Пайплайны и рутины цикла (`/create-article`, `/factcheck`,
`/analyze-article`, `/cycle-plan` и др.) — каждый файл одновременно и
slash-команда, и Skill (описание в frontmatter). Полный список команд и
что каждая делает — `docs/operations.md`, раздел «Карта команд»;
устройство QA-инструментов — `docs/tools.md`.

## MCP и автоматизация

- **GitHub MCP** — PR, коммиты, чтение Actions и логов CI.
- **Claude Code Remote** (Routines, `send_later`) — периодическая
  автоматика без секретов в GitHub Actions: сессия просыпается по
  расписанию, проверяет очередь тем/задач и действует. Не переносится
  на другие инструменты как есть — см. `AGENTS.md` → «Портируемость»
  для эквивалента через GitHub Actions.

## Точки входа для Codex

`.agents/skills/` и `.codex/agents/` — сгенерированные точки входа для
Codex. Руками не править: они собираются из `.claude/commands/` и
`.claude/agents/` скриптом `scripts/codex-sync.mjs` и на них только
ссылаются. Меняете `description` команды или добавляете новую —
`npm run codex:sync`, иначе тест `codex-sync.test.mjs` покраснеет.

Сам переезд — `docs/codex-migration.md`.

## Когда меняется workflow или структура

Обновляйте `AGENTS.md`, если правило универсально (применимо к любому
инструменту), и этот файл, если правило специфично для Claude Code.
Дублировать одно и то же в обоих файлах не нужно — `@AGENTS.md` уже
подтягивает общий файл целиком.
